## 一、值类型 vs 引用类型（10题）

### ⭐ Q1: 什么是值类型和引用类型？有什么区别？

**【答案】**

在C#中，所有数据类型分为两大类：**值类型(Value Type)** 和 **引用类型(Reference Type)**。

**值类型：**
- **定义**：直接存储数据值
- **存储位置**：栈(Stack)内存
- **包括**：`int`, `float`, `double`, `bool`, `char`, `struct`, `enum` 等
- **赋值行为**：复制整个数据值（深拷贝）
- **默认值**：数值类型为0，bool为false

**引用类型：**
- **定义**：存储数据的内存地址（引用）
- **存储位置**：堆(Heap)内存，变量本身在栈上存储地址
- **包括**：`class`, `interface`, `delegate`, `string`, `array`, `object` 等
- **赋值行为**：复制引用地址，指向同一对象（浅拷贝）
- **默认值**：`null`

**代码示例：**

```csharp
// ═══════════════════════════════════
// 值类型示例
// ═══════════════════════════════════
int a = 10;
int b = a;     // 复制值，b 得到 10
b = 20;        // 修改 b 不影响 a

Console.WriteLine(a);  // 输出: 10
Console.WriteLine(b);  // 输出: 20

// ═══════════════════════════════════
// 引用类型示例
// ═══════════════════════════════════
class Person
{
    public string Name { get; set; }
}

Person p1 = new Person { Name = "张三" };
Person p2 = p1;  // 复制引用，p1 和 p2 指向同一对象

p2.Name = "李四";  // 通过 p2 修改，p1 也会变

Console.WriteLine(p1.Name);  // 输出: 李四
Console.WriteLine(p2.Name);  // 输出: 李四
```

**内存示意图：**

```
值类型（栈内存）:
┌────────┐
│ a = 10 │  变量 a 直接存储值 10
└────────┘
┌────────┐
│ b = 20 │  变量 b 直接存储值 20
└────────┘

引用类型（栈+堆）:
栈内存               堆内存
┌──────────┐       ┌─────────────────┐
│ p1: 0x100│──────>│ Person 对象     │
└──────────┘       │ Name = "李四"   │
┌──────────┐       └─────────────────┘
│ p2: 0x100│──────>  （同一个对象）
└──────────┘
```

**【常见误区】**

1. ❌ **错误认知**：`string` 是值类型
   - ✅ **正确**：`string` 是引用类型，但因为不可变性(Immutable)表现像值类型

2. ❌ **错误认知**：数组是值类型
   - ✅ **正确**：数组是引用类型

3. ❌ **混淆** `struct` 和 `class` 的区别
   - `struct` 是值类型
   - `class` 是引用类型

**【扩展知识】**

**为什么 string 表现像值类型？**

```csharp
string s1 = "Hello";
string s2 = s1;
s2 = "World";  // 看起来修改了 s2，但 s1 没变

Console.WriteLine(s1);  // 输出: Hello
Console.WriteLine(s2);  // 输出: World
```

原因：字符串是**不可变的(Immutable)**。
- `s2 = "World"` 实际上创建了一个新的字符串对象
- `s2` 指向新对象，`s1` 仍指向原对象

**【面试追问】**

**Q**: 为什么值类型放在栈上，引用类型放在堆上？

**A**:
- **栈内存**：
  - 访问速度快（LIFO结构）
  - 大小固定，适合小数据
  - 自动管理（离开作用域自动释放）

- **堆内存**：
  - 适合存储大对象
  - 大小不固定
  - 需要垃圾回收器(GC)管理

值类型通常很小（如 int 只有4字节），放栈上效率高。
引用类型可能很大，放堆上更合理。

### ⭐ Q2: struct 和 class 有什么区别？

**【答案】**

| 特性 | struct（结构体） | class（类） |
|------|-----------------|------------|
| **类型** | 值类型 | 引用类型 |
| **存储位置** | 栈（通常） | 堆 |
| **继承** | 不能继承其他类/结构体 | 可以继承类 |
| **默认值** | 自动初始化所有字段 | `null` |
| **构造函数** | 不能有无参构造函数（C# 10前） | 可以有 |
| **析构函数** | 不能有 | 可以有 |
| **性能** | 小数据时更快 | 大对象时更合理 |
| **适用场景** | 小型数据结构（如坐标、颜色） | 复杂对象 |

**代码示例：**

```csharp
// ═══════════════════════════════════
// struct（值类型）
// ═══════════════════════════════════
struct Point
{
    public int X;
    public int Y;

    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
}

Point p1 = new Point(10, 20);
Point p2 = p1;  // 复制整个结构体
p2.X = 30;      // 修改 p2 不影响 p1

Console.WriteLine(p1.X);  // 输出: 10
Console.WriteLine(p2.X);  // 输出: 30

// ═══════════════════════════════════
// class（引用类型）
// ═══════════════════════════════════
class Rectangle
{
    public int Width;
    public int Height;

    public Rectangle(int width, int height)
    {
        Width = width;
        Height = height;
    }
}

Rectangle r1 = new Rectangle(100, 50);
Rectangle r2 = r1;  // 复制引用
r2.Width = 200;     // 修改 r2 也会影响 r1

Console.WriteLine(r1.Width);  // 输出: 200（受影响）
Console.WriteLine(r2.Width);  // 输出: 200
```

**【常见误区】**

1. ❌ **误区**：struct 总是比 class 快
   - ✅ **正确**：只有小数据时才快，大数据时复制成本高

2. ❌ **误区**：struct 不能有方法
   - ✅ **正确**：struct 可以有方法、属性、事件

**【扩展知识】**

**什么时候用 struct？**

微软推荐：
- 表示单个值（如坐标、复数）
- 大小小于 16 字节
- 逻辑上不可变（Immutable）
- 不需要装箱（Boxing）

**WPF 中的 struct 示例**：
```csharp
public struct Point      // 坐标点
public struct Size       // 尺寸
public struct Thickness  // 边距
public struct Color      // 颜色
```

**【面试追问】**

**Q**: 如果 struct 很大（如100个字段），会有什么问题？

**A**:
- 每次赋值都复制整个结构体，性能低
- 栈空间有限（约1MB），可能栈溢出
- 建议改用 class

### ⭐ Q3: 什么是装箱(Boxing)和拆箱(Unboxing)？

**【答案】**

**装箱(Boxing)**：将值类型转换为引用类型（`object` 或接口）
**拆箱(Unboxing)**：将引用类型转换回值类型

**为什么需要装箱？**

C# 中所有类型都继承自 `object`（引用类型），但值类型存储在栈上。
当需要将值类型当作 `object` 使用时，必须装箱。

**代码示例：**

```csharp
// ═══════════════════════════════════
// 装箱（Boxing）
// ═══════════════════════════════════
int i = 123;           // 值类型，存储在栈上
object obj = i;        // 装箱：将 int 转换为 object

// 内部发生的事：
// 1. 在堆上分配内存
// 2. 将值复制到堆上
// 3. 返回堆上对象的引用

// ═══════════════════════════════════
// 拆箱（Unboxing）
// ═══════════════════════════════════
int j = (int)obj;      // 拆箱：将 object 转换回 int

// 内部发生的事：
// 1. 检查obj确实是一个装箱的int
// 2. 从堆上复制值到栈上
```

**内存示意图：**

```
装箱前：
栈              堆
┌──────┐
│i = 123│
└──────┘

装箱后：
栈              堆
┌──────┐      ┌─────────────┐
│i = 123│      │ object      │
└──────┘      │ value = 123 │ ← obj 指向这里
┌──────┐      └─────────────┘
│obj   │──────>
└──────┘
```

**性能影响：**

```csharp
// ❌ 坏的做法：频繁装箱
ArrayList list = new ArrayList();
for (int i = 0; i < 1000000; i++)
{
    list.Add(i);  // 每次循环都装箱，性能差！
}

// ✅ 好的做法：使用泛型避免装箱
List<int> list = new List<int>();
for (int i = 0; i < 1000000; i++)
{
    list.Add(i);  // 不装箱，性能好！
}
```

**【常见误区】**

1. ❌ **误区**：装箱后的对象和原值类型共享数据
   ```csharp
   int i = 10;
   object obj = i;  // 装箱
   i = 20;          // 修改原值
   Console.WriteLine((int)obj);  // 输出: 10（不是20）
   ```
   ✅ **正确**：装箱时复制了值，两者独立

2. ❌ **误区**：拆箱可以转换成任意类型
   ```csharp
   int i = 123;
   object obj = i;
   long l = (long)obj;  // ❌ 运行时异常！
   ```
   ✅ **正确**：只能拆箱为原始类型，需要先拆箱再转换
   ```csharp
   long l = (long)(int)obj;  // ✅ 正确
   ```

**【扩展知识】**

**隐式装箱的常见场景：**

```csharp
// 1. 传递给 object 参数
void PrintValue(object obj) { }
PrintValue(123);  // 隐式装箱

// 2. 字符串连接
string s = "Value: " + 123;  // 装箱

// 3. 集合（非泛型）
ArrayList list = new ArrayList();
list.Add(123);  // 装箱

// 4. 实现接口
interface IComparable { }
struct MyStruct : IComparable { }
MyStruct s = new MyStruct();
IComparable c = s;  // 装箱
```

**【面试追问】**

**Q**: 如何避免装箱带来的性能问题？

**A**:
1. 使用泛型集合（`List<T>` 代替 `ArrayList`）
2. 避免将值类型转换为 `object`
3. 使用 `String.Format` 时注意（改用插值字符串 `$""`）
4. 性能关键代码中避免装箱

### Q4: null 和 default 有什么区别？

**【答案】**

**`null`**：
- 只能用于引用类型和可空值类型
- 表示"没有引用任何对象"

**`default`**：
- 可以用于任何类型
- 返回类型的默认值

**代码示例：**

```csharp
// ═══════════════════════════════════
// 引用类型
// ═══════════════════════════════════
string s1 = null;           // ✅ 可以
string s2 = default;        // ✅ 等同于 null
string s3 = default(string);// ✅ 完整写法

// ═══════════════════════════════════
// 值类型
// ═══════════════════════════════════
int i1 = null;              // ❌ 编译错误！值类型不能为 null
int i2 = default;           // ✅ 等于 0
int i3 = default(int);      // ✅ 等于 0

bool b = default;           // ✅ 等于 false
DateTime dt = default;      // ✅ 等于 0001-01-01 00:00:00

// ═══════════════════════════════════
// 可空值类型
// ═══════════════════════════════════
int? ni1 = null;            // ✅ 可以
int? ni2 = default;         // ✅ 等同于 null
```

**默认值表：**

| 类型 | default 值 |
|------|-----------|
| `int`, `long`, `byte` 等数值 | `0` |
| `float`, `double`, `decimal` | `0.0` |
| `bool` | `false` |
| `char` | `'\0'`（空字符） |
| `DateTime` | `0001-01-01 00:00:00` |
| `string` | `null` |
| `class` | `null` |
| `struct` | 所有字段为默认值的实例 |
| `T?`（可空类型） | `null` |

**【常见误区】**

❌ **误区**：`default(string)` 返回空字符串 `""`
✅ **正确**：返回 `null`

```csharp
string s = default(string);
Console.WriteLine(s == null);   // True
Console.WriteLine(s == "");     // False
```

**【扩展知识】**

**泛型中的 default**：

```csharp
public T GetDefaultValue<T>()
{
    return default(T);  // 或 default（C# 7.1+）
}

int i = GetDefaultValue<int>();        // 0
string s = GetDefaultValue<string>();  // null
bool b = GetDefaultValue<bool>();      // false
```

**【面试追问】**

**Q**: C# 8.0 引入的可空引用类型是什么？

**A**:
可空引用类型允许编译器检查 null 安全：

```csharp
#nullable enable

string s1 = null;   // ⚠️ 警告：不应该为 null
string? s2 = null;  // ✅ 明确声明可以为 null

void Print(string s)
{
    Console.WriteLine(s.Length);  // 假设 s 不为 null
}

Print(s2);  // ⚠️ 警告：可能传入 null
```

### Q5: ref、out 和 in 参数修饰符有什么区别？

**【答案】**

| 修饰符 | 传递方式 | 调用前赋值 | 方法内赋值 | 适用场景 |
|--------|---------|-----------|-----------|---------|
| `ref` | 引用传递 | **必须** | 可选 | 双向传递，修改调用者变量 |
| `out` | 引用传递 | 不需要 | **必须** | 返回多个值 |
| `in` | 引用传递（只读） | **必须** | **禁止** | 传递大型结构体，避免复制 |
| 默认 | 值传递 | - | - | 普通参数 |

**代码示例：**

```csharp
// ═══════════════════════════════════
// ref - 双向传递
// ═══════════════════════════════════
void Swap(ref int a, ref int b)
{
    int temp = a;
    a = b;
    b = temp;
}

int x = 10, y = 20;
Swap(ref x, ref y);
Console.WriteLine($"x={x}, y={y}");  // x=20, y=10

// ═══════════════════════════════════
// out - 返回多个值
// ═══════════════════════════════════
bool TryParse(string input, out int result)
{
    if (int.TryParse(input, out result))
    {
        return true;  // 解析成功
    }
    result = 0;       // 必须赋值
    return false;     // 解析失败
}

if (TryParse("123", out int num))
{
    Console.WriteLine(num);  // 123
}

// ═══════════════════════════════════
// in - 只读引用传递（避免大对象复制）
// ═══════════════════════════════════
struct LargeStruct  // 假设这是一个很大的结构体
{
    public int Value1;
    public int Value2;
    // ... 很多字段
}

void Process(in LargeStruct data)
{
    Console.WriteLine(data.Value1);
    // data.Value1 = 10;  // ❌ 编译错误！不能修改
}

LargeStruct s = new LargeStruct { Value1 = 100 };
Process(in s);  // 不复制，直接传递引用
```

**【常见误区】**

1. ❌ **误区**：`out` 参数调用前必须赋值
   ```csharp
   int result;  // 不需要赋值
   TryParse("123", out result);  // ✅ 正确
   ```

2. ❌ **误区**：`ref` 可以用于返回值
   ```csharp
   // ✅ C# 7.0+ 支持 ref 返回值
   ref int GetFirst(int[] array)
   {
       return ref array[0];
   }
   ```

**【扩展知识】**

**C# 7.0+ 的 out 变量声明：**

```csharp
// 旧写法
int num;
if (int.TryParse("123", out num))
{
    Console.WriteLine(num);
}

// 新写法（C# 7.0+）
if (int.TryParse("123", out int num))
{
    Console.WriteLine(num);
}

// 或者使用弃元（不需要的值）
if (int.TryParse("123", out _))
{
    // 只关心是否成功，不需要结果
}
```

**【面试追问】**

**Q**: 为什么要用 `in` 而不是普通参数？

**A**:
```csharp
// 普通参数（值传递）
void Process(LargeStruct data)  // 复制整个结构体，慢！
{
    // ...
}

// in 参数（引用传递，只读）
void Process(in LargeStruct data)  // 只传递引用，快！
{
    // ...（不能修改）
}
```

适用于：
- 大型结构体（>16字节）
- 只读访问
- 性能关键代码

### Q6: 可空类型(Nullable Types)是什么？

**【答案】**

**可空类型**允许值类型具有 `null` 值。

**语法：**
```csharp
int? nullableInt = null;      // 简写
Nullable<int> nullableInt2 = null;  // 完整写法
```

**为什么需要可空类型？**

数据库中的字段可能为 `NULL`，但 C# 的值类型不能为 `null`：

```csharp
// 数据库查询结果
// ID   Age
// 1    25
// 2    NULL  ← 如何表示？

// ❌ 不能用 int，因为 Age 可能为 NULL
int age = GetAgeFromDatabase(2);  // 如果是 NULL 怎么办？

// ✅ 用 int?
int? age = GetAgeFromDatabase(2);  // 可以是 null
```

**代码示例：**

```csharp
// ═══════════════════════════════════
// 基本用法
// ═══════════════════════════════════
int? age = null;

if (age.HasValue)
{
    Console.WriteLine(age.Value);  // 获取实际值
}
else
{
    Console.WriteLine("Age is null");
}

// ═══════════════════════════════════
// 空合并运算符 ??
// ═══════════════════════════════════
int? nullableAge = null;
int age = nullableAge ?? 18;  // 如果为 null，使用默认值 18

Console.WriteLine(age);  // 18

// ═══════════════════════════════════
// 空条件运算符 ?.
// ═══════════════════════════════════
int? nullableInt = null;
int? result = nullableInt?.ToString().Length;  // 如果为 null，整个表达式为 null

// ═══════════════════════════════════
// GetValueOrDefault()
// ═══════════════════════════════════
int? age1 = null;
int defaultAge = age1.GetValueOrDefault();  // 0（int 的默认值）

int? age2 = 25;
int actualAge = age2.GetValueOrDefault();  // 25
```

**【常见误区】**

1. ❌ **误区**：可空类型占用额外很多内存
   ```csharp
   int i;      // 4 字节
   int? ni;    // 5 字节（4字节值 + 1字节标志）
   ```
   ✅ **正确**：只多占用 1 个字节（用于存储是否有值的标志）

2. ❌ **误区**：`null` 和 `0` 是一样的
   ```csharp
   int? a = null;
   int? b = 0;

   Console.WriteLine(a == b);  // False（null ≠ 0）
   ```

**【扩展知识】**

**可空类型的内部实现：**

```csharp
public struct Nullable<T> where T : struct
{
    private bool hasValue;  // 是否有值
    private T value;        // 实际值

    public bool HasValue => hasValue;

    public T Value
    {
        get
        {
            if (!hasValue)
                throw new InvalidOperationException();
            return value;
        }
    }

    public T GetValueOrDefault() => hasValue ? value : default(T);
}
```

**【面试追问】**

**Q**: C# 8.0 的可空引用类型和可空值类型有什么区别？

**A**:
- **可空值类型**（`int?`）：运行时特性，实际存储 `Nullable<int>` 结构
- **可空引用类型**（`string?`）：编译时特性，仅用于静态分析，运行时没有区别

```csharp
// 可空值类型
int? i = null;  // 运行时真的是 null

// 可空引用类型（C# 8.0+）
string? s = null;  // 编译器帮你检查，运行时和普通 string 一样
```

### Q7: == 和 Equals() 有什么区别？

**【答案】**

| 特性 | `==` 运算符 | `Equals()` 方法 |
|------|------------|----------------|
| **默认行为（值类型）** | 比较值 | 比较值 |
| **默认行为（引用类型）** | 比较引用（地址） | 比较引用（地址） |
| **可重载** | 可以（`operator ==`） | 可以（重写`Equals`） |
| **null 安全** | 是 | 否（调用者为 null 会抛异常） |
| **推荐用法** | 比较基本类型 | 比较复杂对象 |

**代码示例：**

```csharp
// ═══════════════════════════════════
// 值类型：== 和 Equals 都比较值
// ═══════════════════════════════════
int a = 10;
int b = 10;

Console.WriteLine(a == b);        // True
Console.WriteLine(a.Equals(b));   // True

// ═══════════════════════════════════
// 引用类型（默认）：比较引用
// ═══════════════════════════════════
class Person
{
    public string Name { get; set; }
}

Person p1 = new Person { Name = "张三" };
Person p2 = new Person { Name = "张三" };
Person p3 = p1;

Console.WriteLine(p1 == p2);        // False（不同对象）
Console.WriteLine(p1.Equals(p2));   // False（不同对象）
Console.WriteLine(p1 == p3);        // True（同一对象）

// ═══════════════════════════════════
// 字符串（特殊）：== 被重载为比较值
// ═══════════════════════════════════
string s1 = "Hello";
string s2 = "Hello";
string s3 = new string("Hello".ToCharArray());

Console.WriteLine(s1 == s2);        // True（比较值）
Console.WriteLine(s1.Equals(s2));   // True（比较值）
Console.WriteLine(s1 == s3);        // True（==被重载）
Console.WriteLine(ReferenceEquals(s1, s3));  // False（不同对象）

// ═══════════════════════════════════
// null 安全性
// ═══════════════════════════════════
string nullStr = null;

Console.WriteLine(nullStr == null);        // True（安全）
// Console.WriteLine(nullStr.Equals(null));  // ❌ NullReferenceException！
```

**【常见误区】**

1. ❌ **误区**：`==` 总是比较引用
   ```csharp
   string s1 = "abc";
   string s2 = "abc";
   Console.WriteLine(s1 == s2);  // True（string 重载了 ==）
   ```

2. ❌ **误区**：自定义类中 `==` 和 `Equals` 总是一致
   ```csharp
   // 可以重载 == 但不重写 Equals，导致行为不一致（不推荐）
   ```

**【扩展知识】**

**重载 == 和重写 Equals 的最佳实践：**

```csharp
class Person
{
    public string Name { get; set; }
    public int Age { get; set; }

    // 1️⃣ 重写 Equals
    public override bool Equals(object obj)
    {
        if (obj == null || GetType() != obj.GetType())
            return false;

        Person other = (Person)obj;
        return Name == other.Name && Age == other.Age;
    }

    // 2️⃣ 重写 GetHashCode（必须）
    public override int GetHashCode()
    {
        return HashCode.Combine(Name, Age);
    }

    // 3️⃣ 重载 == 和 !=
    public static bool operator ==(Person p1, Person p2)
    {
        if (ReferenceEquals(p1, p2)) return true;
        if (p1 is null || p2 is null) return false;
        return p1.Equals(p2);
    }

    public static bool operator !=(Person p1, Person p2)
    {
        return !(p1 == p2);
    }
}
```

**【面试追问】**

**Q**: 为什么重写 `Equals` 必须同时重写 `GetHashCode`？

**A**:
如果两个对象相等（`Equals` 返回 `true`），它们的哈希码必须相同。
否则在字典(`Dictionary`)和哈希集(`HashSet`)中会出错：

```csharp
Dictionary<Person, string> dict = new Dictionary<Person, string>();

Person p1 = new Person { Name = "张三" };
Person p2 = new Person { Name = "张三" };

dict[p1] = "数据";

// 如果没有正确重写 GetHashCode：
string value = dict[p2];  // ❌ 找不到！虽然 p1.Equals(p2) 为 true
```

### Q8: is 和 as 关键字有什么区别？

**【答案】**

| 特性 | `is` | `as` |
|------|------|------|
| **作用** | 检查类型是否兼容 | 尝试转换类型 |
| **返回类型** | `bool` | 转换后的对象或 `null` |
| **转换失败** | 返回 `false` | 返回 `null` |
| **性能** | 快（仅检查） | 稍慢（检查+转换） |
| **适用场景** | 类型检查 | 安全转换 |

**代码示例：**

```csharp
// ═══════════════════════════════════
// is - 类型检查
// ═══════════════════════════════════
object obj = "Hello";

if (obj is string)
{
    Console.WriteLine("obj 是字符串");
}

// C# 7.0+ 模式匹配
if (obj is string str)
{
    Console.WriteLine(str.Length);  // 直接使用转换后的变量
}

// ═══════════════════════════════════
// as - 安全转换
// ═══════════════════════════════════
object obj2 = "World";

string s = obj2 as string;
if (s != null)
{
    Console.WriteLine(s.Length);
}

// ═══════════════════════════════════
// 对比：强制转换
// ═══════════════════════════════════
object obj3 = 123;

// ❌ 强制转换（可能抛异常）
string s1 = (string)obj3;  // InvalidCastException！

// ✅ as 转换（安全）
string s2 = obj3 as string;  // null（不抛异常）

// ✅ is + 强制转换
if (obj3 is string)
{
    string s3 = (string)obj3;  // 安全
}
```

**【常见误区】**

1. ❌ **误区**：`as` 可以用于值类型
   ```csharp
   object obj = 123;
   int i = obj as int;  // ❌ 编译错误！
   ```
   ✅ **正确**：`as` 只能用于引用类型和可空值类型
   ```csharp
   int? i = obj as int?;  // ✅ 正确
   ```

2. ❌ **误区**：`is` 比 `as` 效率高，总是用 `is`
   ✅ **正确**：如果需要转换，用 `as` 更高效（只检查一次）
   ```csharp
   // ❌ 低效：检查两次
   if (obj is string)
   {
       string s = (string)obj;  // 又检查又转换
   }

   // ✅ 高效：只检查一次
   string s = obj as string;
   if (s != null)
   {
       // 使用 s
   }

   // ✅ 更高效：C# 7.0+ 模式匹配
   if (obj is string s)
   {
       // 使用 s
   }
   ```

**【扩展知识】**

**C# 7.0+ 模式匹配增强：**

```csharp
object obj = 42;

// 类型检查+变量声明
if (obj is int number)
{
    Console.WriteLine(number * 2);
}

// null 检查
if (obj is null)
{
    Console.WriteLine("obj is null");
}

// switch 模式匹配
string result = obj switch
{
    int i => $"整数: {i}",
    string s => $"字符串: {s}",
    null => "null",
    _ => "其他类型"
};
```

**【面试追问】**

**Q**: `is` 和 `GetType()` 有什么区别？

**A**:
```csharp
class Animal { }
class Dog : Animal { }

Dog dog = new Dog();
Animal animal = dog;

// is - 检查对象是否"是"指定类型（包括继承）
Console.WriteLine(animal is Dog);     // True
Console.WriteLine(animal is Animal);  // True

// GetType - 获取实际类型（不包括基类）
Console.WriteLine(animal.GetType() == typeof(Dog));     // True
Console.WriteLine(animal.GetType() == typeof(Animal));  // False
```

- `is`：支持继承检查（协变）
- `GetType()`：精确类型匹配

### Q10: 值类型为什么不能继承？

**【答案】**

值类型（`struct`）**不能继承其他类或被继承**，原因：

**1️⃣ 内存布局**

```
class（引用类型）：
栈                  堆
┌──────────┐      ┌──────────────────┐
│ obj: 引用 │─────>│  对象头（类型信息）│
└──────────┘      │  字段1           │
                  │  字段2           │
                  └──────────────────┘

struct（值类型）：
栈
┌──────────────┐
│  字段1       │  ← 直接存储数据
│  字段2       │
└──────────────┘
```

引用类型的对象头包含类型信息，支持多态。
值类型直接存储数据，没有对象头，无法支持多态。

**2️⃣ 性能考虑**

```csharp
// 如果 struct 能继承（假设）
struct Base { public int X; }
struct Derived : Base { public int Y; }

Derived d = new Derived();
Base b = d;  // 需要装箱？拷贝？性能损失！
```

**3️⃣ 语义清晰**

- `struct`：简单数据容器，值语义
- `class`：复杂对象，引用语义

**代码示例：**

```csharp
// ❌ struct 不能继承 class
struct MyStruct : MyClass  // 编译错误！
{
}

// ❌ struct 不能继承 struct
struct Base { }
struct Derived : Base  // 编译错误！
{
}

// ✅ struct 可以实现接口
interface IPrintable
{
    void Print();
}

struct Point : IPrintable
{
    public int X, Y;

    public void Print()
    {
        Console.WriteLine($"({X}, {Y})");
    }
}
```

**【常见误区】**

❌ **误区**：值类型完全不能有继承关系
✅ **正确**：所有值类型都隐式继承自 `System.ValueType`

```csharp
struct Point { }

Console.WriteLine(typeof(Point).BaseType);  // System.ValueType
Console.WriteLine(typeof(ValueType).BaseType);  // System.Object
```

继承层次：
```
object
  └─ ValueType
       ├─ int
       ├─ bool
       ├─ Point（自定义 struct）
       └─ ...
```

**【扩展知识】**

**为什么 ValueType 是 class？**

```csharp
// ValueType 的定义（简化）
public abstract class ValueType
{
    public override bool Equals(object obj)
    {
        // 默认实现：逐字段比较
    }

    public override int GetHashCode()
    {
        // 默认实现：基于字段计算哈希
    }
}
```

`ValueType` 是 `class`，但继承自它的类型会被编译器特殊处理为值类型。

**【面试追问】**

**Q**: `record struct`（C# 10+）和普通 `struct` 有什么区别？

**A**:
```csharp
// 普通 struct
struct Point
{
    public int X;
    public int Y;
}

// record struct（C# 10+）
record struct Point2(int X, int Y);

// 区别：
// 1. 自动实现 Equals、GetHashCode、ToString
// 2. 支持解构
// 3. with 表达式
Point2 p1 = new Point2(10, 20);
Point2 p2 = p1 with { X = 30 };  // 创建修改后的副本

Console.WriteLine(p1);  // Point2 { X = 10, Y = 20 }
```

## 🎯 第一部分小结

**核心要点**：
1. 值类型存栈，引用类型存堆
2. `struct` 是值类型，`class` 是引用类型
3. 装箱/拆箱性能损耗大，用泛型避免
4. `null` 只能用于引用类型和可空值类型
5. `ref`/`out`/`in` 用于引用传递
6. `==` vs `Equals()`：注意重载情况
7. `is` 检查类型，`as` 安全转换
8. `typeof` 编译时，`GetType()` 运行时

**建议背诵**：
- 值类型 vs 引用类型的区别表
- `ref`/`out`/`in` 的区别表
- `==` vs `Equals()` 的区别表

## 二、类、接口、抽象类（8题）

### ⭐ Q11: 抽象类(abstract class)和接口(interface)有什么区别？

**【答案】**

| 特性 | 抽象类 | 接口 |
|------|--------|------|
| **关键字** | `abstract class` | `interface` |
| **继承** | 一个类只能继承一个抽象类 | 可以实现多个接口 |
| **成员** | 可以有字段、属性、方法、构造函数 | 只能有方法签名、属性签名（C# 8.0前） |
| **访问修饰符** | 成员可以有任意修饰符 | 成员默认 `public`（C# 8.0前） |
| **实现** | 可以有默认实现 | 只能有签名（C# 8.0后可有默认实现） |
| **构造函数** | 可以有 | 不能有 |
| **适用场景** | "is-a" 关系（猫是动物） | "can-do" 关系（猫能跑） |

**代码示例：**

```csharp
// ═══════════════════════════════════
// 抽象类
// ═══════════════════════════════════
abstract class Animal
{
    // 字段
    protected string name;

    // 构造函数
    public Animal(string name)
    {
        this.name = name;
    }

    // 抽象方法（子类必须实现）
    public abstract void MakeSound();

    // 普通方法（有默认实现）
    public virtual void Sleep()
    {
        Console.WriteLine($"{name} is sleeping");
    }
}

class Dog : Animal
{
    public Dog(string name) : base(name) { }

    public override void MakeSound()
    {
        Console.WriteLine("汪汪汪");
    }
}

// ═══════════════════════════════════
// 接口
// ═══════════════════════════════════
interface IRunnable
{
    void Run();
}

interface ISwimmable
{
    void Swim();
}

// 可以实现多个接口
class Duck : Animal, IRunnable, ISwimmable
{
    public Duck(string name) : base(name) { }

    public override void MakeSound()
    {
        Console.WriteLine("嘎嘎嘎");
    }

    public void Run()
    {
        Console.WriteLine("Duck is running");
    }

    public void Swim()
    {
        Console.WriteLine("Duck is swimming");
    }
}
```

**【常见误区】**

❌ **误区**：抽象类不能实例化，所以没用
✅ **正确**：抽象类可以通过子类实例化，提供公共实现

```csharp
// Animal animal = new Animal();  // ❌ 编译错误
Animal dog = new Dog("旺财");     // ✅ 正确
dog.MakeSound();
```

**【扩展知识】**

**C# 8.0+ 接口默认实现：**

```csharp
interface ILogger
{
    void Log(string message);

    // 默认实现
    void LogError(string error)
    {
        Log($"ERROR: {error}");
    }
}

class ConsoleLogger : ILogger
{
    public void Log(string message)
    {
        Console.WriteLine(message);
    }

    // 不需要实现 LogError，使用默认实现
}

// 使用
ILogger logger = new ConsoleLogger();
logger.LogError("出错了");  // 调用默认实现
```

**【面试追问】**

**Q**: 什么时候用抽象类，什么时候用接口？

**A**:

**用抽象类：**
- 多个类有共同的实现逻辑
- "is-a" 关系（猫是动物）
- 需要字段或构造函数

**用接口：**
- 多个不相关的类需要相同的能力
- "can-do" 关系（鸟能飞，飞机也能飞）
- 需要多重继承

示例：
```csharp
// ✅ 抽象类：动物有共同属性

    protected int age;  // 所有动物都有年龄
    public abstract void MakeSound();
}

// ✅ 接口：不相关的类有共同能力
interface IFlyable
{
    void Fly();
}

class Bird : Animal, IFlyable  // 鸟是动物，能飞
class Airplane : IFlyable      // 飞机能飞，但不是动物
```

### Q12: virtual、abstract 和 override 有什么区别？

**【答案】**

| 关键字 | 用途 | 是否必须重写 | 是否有实现 | 适用类型 |
|--------|------|-------------|-----------|---------|
| `virtual` | 标记可被重写的方法 | 否 | 是 | 普通类 |
| `abstract` | 标记必须被重写的方法 | 是 | 否 | 抽象类 |
| `override` | 重写父类的虚方法或抽象方法 | - | 是 | 子类 |
| `sealed` | 阻止进一步重写 | - | - | 子类 |

**代码示例：**

```csharp
// ═══════════════════════════════════
// virtual - 可选重写
// ═══════════════════════════════════
class Animal
{
    public virtual void MakeSound()
    {
        Console.WriteLine("动物叫声");
    }
}

class Dog : Animal
{
    // 可以选择重写或不重写
    public override void MakeSound()
    {
        Console.WriteLine("汪汪汪");
    }
}

class Cat : Animal
{
    // 不重写，使用父类默认实现
}

// ═══════════════════════════════════
// abstract - 必须重写
// ═══════════════════════════════════
abstract class Shape
{
    // 抽象方法：无实现，子类必须重写
    public abstract double GetArea();

    // 虚方法：有实现，子类可选重写
    public virtual void Draw()
    {
        Console.WriteLine("绘制形状");
    }
}

class Circle : Shape
{
    public double Radius { get; set; }

    // 必须实现抽象方法
    public override double GetArea()
    {
        return Math.PI * Radius * Radius;
    }

    // 可选重写虚方法
    public override void Draw()
    {
        Console.WriteLine("绘制圆形");
    }
}

// ═══════════════════════════════════
// sealed - 阻止重写
// ═══════════════════════════════════
class Rectangle : Shape
{
    public override double GetArea()
    {
        return 0;
    }

    public sealed override void Draw()  // 密封，不允许子类再重写
    {
        Console.WriteLine("绘制矩形");
    }
}

class Square : Rectangle
{
    // public override void Draw()  // ❌ 编译错误！Draw 被 sealed
}
```

**【常见误区】**

1. ❌ **误区**：`virtual` 方法必须被子类重写
   ```csharp
   class Base
   {
       public virtual void Method() { }
   }

   class Derived : Base
   {
       // 不重写也可以，使用父类实现
   }
   ```

2. ❌ **误区**：重写时不用写 `override`
   ```csharp
   class Base
   {
       public virtual void Method() { }
   }

   class Derived : Base
   {
       public void Method() { }  // ❌ 这不是重写，是隐藏（new）
   }

   // 正确写法：
   class Derived : Base
   {
       public override void Method() { }  // ✅ 重写
   }
   ```

**【扩展知识】**

**new 关键字隐藏父类成员：**

```csharp
class Base
{
    public virtual void Method()
    {
        Console.WriteLine("Base");
    }
}

class Derived : Base
{
    public new void Method()  // 隐藏父类方法
    {
        Console.WriteLine("Derived");
    }
}

// 使用
Derived d = new Derived();
d.Method();  // 输出: Derived

Base b = new Derived();
b.Method();  // 输出: Base（调用父类方法）

// 对比 override：
class Derived2 : Base
{
    public override void Method()  // 重写父类方法
    {
        Console.WriteLine("Derived2");
    }
}

Base b2 = new Derived2();
b2.Method();  // 输出: Derived2（多态）
```

**【面试追问】**

**Q**: `virtual` 和 `abstract` 方法在性能上有区别吗？

**A**:
- **虚方法**：运行时通过虚函数表(vtable)查找实际方法，有轻微性能开销
- **抽象方法**：编译后也是虚方法，性能相同
- **密封方法/非虚方法**：直接调用，性能最佳

但在现代.NET运行时中，性能差异可忽略不计。
设计清晰度 > 微小性能差异。
