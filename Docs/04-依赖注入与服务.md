## 什么是依赖注入

### 依赖（Dependency）

**依赖**：一个类使用另一个类的功能。

```csharp
// UserService 依赖 IRepository
public class UserService
{
    private readonly IRepository _repository;  // 依赖

    public UserService(IRepository repository)
    {
        _repository = repository;
    }
}
```

### 注入（Injection）

**注入**：从外部提供依赖，而不是在类内部创建。

```csharp
// ❌ 不使用注入（在类内部 new）
public class UserService
{
    private readonly IRepository _repository = new SqlRepository();  // 硬编码依赖

    // 问题：
    // 1. 难以替换实现（如果想换成 MongoRepository）
    // 2. 难以测试（无法 Mock）
    // 3. 强耦合
}

// ✅ 使用依赖注入（从外部传入）
public class UserService
{
    private readonly IRepository _repository;

    public UserService(IRepository repository)  // 依赖通过构造函数注入
    {
        _repository = repository;
    }

    // 优点：
    // 1. 易于替换实现
    // 2. 易于测试（可以传入 Mock 对象）
    // 3. 低耦合
}
```

### 依赖注入的本质

**核心思想**：控制反转（IoC - Inversion of Control）

```
传统模式：
类自己创建依赖 → 类控制依赖的创建

依赖注入：
外部创建依赖并注入 → 外部（容器）控制依赖的创建
```

## 为什么需要依赖注入

### 问题：紧耦合

```csharp
// ❌ 紧耦合示例
public class LoginViewModel
{
    private NavigationService _navigationService = new NavigationService();  // 直接 new
    private UserService _userService = new UserService();                   // 直接 new

    public void Login()
    {
        var user = _userService.Login(Username, Password);
        if (user != null)
        {
            _navigationService.NavigateTo("Main");
        }
    }
}

// 问题：
// 1. 无法替换实现（如果需要 MockUserService 测试）
// 2. 依赖变化会影响 LoginViewModel（如 UserService 构造函数参数变化）
// 3. 难以单元测试
// 4. 代码复用困难
```

### 解决方案：依赖注入

```csharp
// ✅ 使用依赖注入
public class LoginViewModel
{
    private readonly INavigationService _navigationService;
    private readonly IUserService _userService;

    // 构造函数注入
    public LoginViewModel(INavigationService navigationService, IUserService userService)
    {
        _navigationService = navigationService;
        _userService = userService;
    }

    public void Login()
    {
        var user = _userService.Login(Username, Password);
        if (user != null)
        {
            _navigationService.NavigateTo("Main");
        }
    }
}

// 优点：
// 1. 易于替换实现（注入不同的服务）
// 2. 解耦（ViewModel 不关心服务如何创建）
// 3. 易于测试（注入 Mock 对象）
// 4. 代码复用
```

**单元测试示例**：

```csharp
// 测试代码
[TestMethod]
public void Login_WithValidUser_ShouldNavigateToMain()
{
    // Arrange：准备 Mock 对象
    var mockNavigation = new Mock<INavigationService>();
    var mockUserService = new Mock<IUserService>();
    mockUserService.Setup(s => s.Login(It.IsAny<string>(), It.IsAny<string>()))
                   .Returns(new User { Id = 1, Name = "Test" });

    var viewModel = new LoginViewModel(mockNavigation.Object, mockUserService.Object);
    viewModel.Username = "test";
    viewModel.Password = "password";

    // Act：执行操作
    viewModel.Login();

    // Assert：验证结果
    mockNavigation.Verify(n => n.NavigateTo("Main"), Times.Once);
}
```

## IoC 容器

### 什么是 IoC 容器？

**IoC 容器（Inversion of Control Container）**：负责创建对象并自动解析依赖的工具。

**工作流程**：

```
1. 注册阶段：
   container.Register<IUserService, UserService>();
   container.Register<INavigationService, NavigationService>();
   container.Register<LoginViewModel>();

2. 解析阶段：
   var viewModel = container.Resolve<LoginViewModel>();

3. 容器自动处理：
   - 创建 UserService 实例
   - 创建 NavigationService 实例
   - 将它们注入到 LoginViewModel 构造函数
   - 创建并返回 LoginViewModel 实例
```

**手动创建 vs 容器创建**：

```csharp
// ❌ 手动创建（繁琐且易出错）
var repository = new SqlRepository();
var userService = new UserService(repository);
var navigationService = new NavigationService();
var loginViewModel = new LoginViewModel(navigationService, userService);

// ✅ 容器创建（简单清晰）
var loginViewModel = container.GetService<LoginViewModel>();
// 容器自动创建所有依赖并注入
```

### 依赖链自动解析

```csharp
// 复杂的依赖链
public class LoginViewModel
{
    public LoginViewModel(INavigationService nav, IUserService user) { }
}

public class NavigationService : INavigationService
{
    public NavigationService(IServiceProvider provider) { }
}

public class UserService : IUserService
{
    public UserService(IRepository repo, ILogger logger) { }
}

public class SqlRepository : IRepository
{
    public SqlRepository(IDbConnection conn) { }
}

// 手动创建需要 5 个步骤！
// 容器只需要 1 行：
var loginViewModel = container.GetService<LoginViewModel>();
// 容器自动解析整个依赖链
```

## 服务生命周期

### 三种生命周期

**Singleton（单例）**：全局唯一实例
**Transient（瞬态）**：每次请求都创建新实例
**Scoped（作用域）**：同一作用域内共享实例

### 1. Singleton（单例）

```csharp
services.AddSingleton<INavigationService, NavigationService>();
```

**特点**：
- 应用程序启动时创建一次
- 全局共享同一个实例
- 应用程序关闭时销毁

**适用场景**：
- 无状态服务
- 共享状态（配置、缓存）
- 性能敏感（避免重复创建）

**示例**：

```csharp
// 注册为 Singleton
services.AddSingleton<INavigationService, NavigationService>();

// 获取实例
var nav1 = serviceProvider.GetService<INavigationService>();
var nav2 = serviceProvider.GetService<INavigationService>();

// nav1 和 nav2 是同一个对象
Console.WriteLine(nav1 == nav2);  // True
```

**内存示意图**：

```
Application Lifetime
├─ NavigationService (Singleton) ← 唯一实例
│   ├─ Page 1 使用 ───┐
│   ├─ Page 2 使用 ───┤ 所有地方共享同一实例
│   └─ Page 3 使用 ───┘
```

### 2. Transient（瞬态）

```csharp
services.AddTransient<LoginViewModel>();
```

**特点**：
- 每次请求都创建新实例
- 不共享状态
- 使用完毕后由 GC 回收

**适用场景**：
- 轻量级无状态服务
- ViewModel（每个页面独立状态）
- 短生命周期对象

**示例**：

```csharp
// 注册为 Transient
services.AddTransient<LoginViewModel>();

// 获取实例
var vm1 = serviceProvider.GetService<LoginViewModel>();
var vm2 = serviceProvider.GetService<LoginViewModel>();

// vm1 和 vm2 是不同对象
Console.WriteLine(vm1 == vm2);  // False
```

**内存示意图**：

```
Request 1
└─ LoginViewModel Instance 1 (独立)

Request 2
└─ LoginViewModel Instance 2 (独立)

Request 3
└─ LoginViewModel Instance 3 (独立)
```

### 3. Scoped（作用域）

```csharp
services.AddScoped<IDbContext, AppDbContext>();
```

**特点**：
- 同一作用域内共享实例
- 不同作用域有不同实例
- 作用域结束时销毁

**适用场景**：
- 数据库上下文（EF Core）
- Web 请求范围（每个 HTTP 请求一个实例）
- **WPF 中较少使用**（通常用 Singleton 或 Transient）

**Web 示例**（理解概念）：

```csharp
// ASP.NET Core
services.AddScoped<IDbContext, AppDbContext>();

// 同一 HTTP 请求内：
var db1 = serviceProvider.GetService<IDbContext>();
var db2 = serviceProvider.GetService<IDbContext>();
// db1 == db2 (同一请求，同一实例)

// 不同 HTTP 请求：
// 请求 A 有自己的 DbContext
// 请求 B 有自己的 DbContext
```

### 生命周期对比表

| 生命周期 | 创建时机 | 销毁时机 | 是否共享 | 适用场景 |
|---------|---------|---------|---------|---------|
| Singleton | 应用启动时 | 应用关闭时 | 全局共享 | 无状态服务、配置 |
| Transient | 每次请求时 | 使用后 GC | 不共享 | ViewModel、轻量服务 |
| Scoped | 作用域创建时 | 作用域结束时 | 作用域内共享 | 数据库上下文（Web） |

### 生命周期选择指南

```csharp
// Singleton：全局唯一，共享状态
services.AddSingleton<INavigationService, NavigationService>();
services.AddSingleton<IConfiguration, Configuration>();

// Transient：每次创建，独立状态
services.AddTransient<LoginViewModel>();
services.AddTransient<DataViewModel>();

// Scoped：WPF 中较少用，主要用于 Web
// services.AddScoped<IDbContext, AppDbContext>();
```

**注意事项**：

```csharp
// ⚠️ 警告：Singleton 依赖 Transient（危险）
services.AddSingleton<MySingletonService>();  // MySingletonService 依赖 ITransientService
services.AddTransient<ITransientService, MyTransientService>();

// 问题：MySingletonService 只创建一次
// → 它持有的 ITransientService 也只创建一次
// → 违背了 Transient 的本意

// ✅ 正确：Singleton 应该依赖 Singleton
// ✅ 正确：Transient 可以依赖 Singleton
```

## Microsoft.Extensions.DependencyInjection

### 安装 NuGet 包

```xml
<PackageReference Include="Microsoft.Extensions.DependencyInjection" Version="8.0.0" />
```

### 基本使用

```csharp
using Microsoft.Extensions.DependencyInjection;

// 1. 创建服务容器
var services = new ServiceCollection();

// 2. 注册服务
services.AddSingleton<INavigationService, NavigationService>();
services.AddTransient<LoginViewModel>();

// 3. 构建服务提供者
var serviceProvider = services.BuildServiceProvider();

// 4. 解析服务
var navigationService = serviceProvider.GetService<INavigationService>();
var loginViewModel = serviceProvider.GetService<LoginViewModel>();
```

### 服务注册方法

```csharp
// 方式 1：泛型方法
services.AddSingleton<INavigationService, NavigationService>();

// 方式 2：Type 参数
services.AddSingleton(typeof(INavigationService), typeof(NavigationService));

// 方式 3：工厂方法
services.AddSingleton<INavigationService>(provider =>
{
    // 自定义创建逻辑
    return new NavigationService(provider);
});

// 方式 4：实例注册
var instance = new NavigationService();
services.AddSingleton<INavigationService>(instance);

// 方式 5：只注册实现类（无接口）
services.AddTransient<LoginViewModel>();
```

### 服务解析方法

```csharp
// GetService：找不到返回 null
var service1 = serviceProvider.GetService<INavigationService>();
if (service1 == null)
{
    // 处理未注册的情况
}

// GetRequiredService：找不到抛异常
var service2 = serviceProvider.GetRequiredService<INavigationService>();
// 如果未注册，抛出 InvalidOperationException

// GetServices：获取所有注册的实现
var services = serviceProvider.GetServices<INotificationService>();
// 返回 IEnumerable<INotificationService>
```

## 项目中的 DI 实现

### App.xaml.cs 配置

```csharp
public partial class App : Application
{
    private static IServiceProvider? _serviceProvider;

    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);

        // 1. 创建服务集合
        var services = new ServiceCollection();

        // 2. 配置服务
        ConfigureServices(services);

        // 3. 构建服务提供者
        _serviceProvider = services.BuildServiceProvider();

        // 4. 显示主窗口
        var loginWindow = GetService<Login>();
        loginWindow?.Show();
    }

    private void ConfigureServices(IServiceCollection services)
    {
        // 注册服务（Singleton）
        services.AddSingleton<INavigationService, NavigationService>();

        // 注册 ViewModels（Transient）
        services.AddTransient<LoginViewModel>();
        services.AddTransient<MainWindowViewModel>();
        services.AddTransient<DataViewModel>();
        services.AddTransient<EditViewModel>();
        services.AddTransient<EquipmentInfoViewModel>();

        // 注册 Views（Transient）
        services.AddTransient<Login>();
        services.AddTransient<MainWindow>();
        services.AddTransient<Data>();
        services.AddTransient<Edit>();
        services.AddTransient<EquipmentInfo>();

        // 注册导航页面
        var navigationService = services.BuildServiceProvider()
                                       .GetRequiredService<INavigationService>();
        navigationService.RegisterPage<Data>("Data");
        navigationService.RegisterPage<Edit>("Edit");
        navigationService.RegisterPage<EquipmentInfo>("EquipmentInfo");
        navigationService.RegisterPage<ReservationList>("ReservationList");
    }

    // 静态方法：在任何地方获取服务
    public static T GetService<T>() where T : class
    {
        return _serviceProvider?.GetService<T>()
            ?? throw new InvalidOperationException($"服务 {typeof(T)} 未注册");
    }
}
```

### View 中使用 DI

```csharp
// Login.xaml.cs
public partial class Login : Page
```

```csharp
public partial class LoginViewModel : ObservableObject
{
```

## 常见服务模式

### 1. 导航服务（INavigationService）

```csharp
// 接口定义
public interface INavigationService
{
    void NavigateTo(string pageKey, object? parameter = null);
    bool GoBack();
    void ClearHistory();
    Page? CurrentPage { get; }
    event EventHandler<Page?>? CurrentPageChanged;
}

// 实现
public class NavigationService : INavigationService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly Dictionary<string, Type> _pageTypes = new();
    private readonly Stack<Page> _navigationHistory = new();

    public NavigationService(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }

    public void RegisterPage<T>(string key) where T : Page
    {
        _pageTypes[key] = typeof(T);
    }

    public void NavigateTo(string pageKey, object? parameter = null)
    {
        if (!_pageTypes.TryGetValue(pageKey, out var pageType))
            throw new ArgumentException($"页面 '{pageKey}' 未注册");

        // 通过 DI 容器创建页面
        var page = (Page)_serviceProvider.GetRequiredService(pageType);

        // 传递参数
        if (page.DataContext is INavigationAware navigationAware)
            navigationAware.OnNavigatedTo(parameter);

        _navigationHistory.Push(CurrentPage);
        CurrentPage = page;
        CurrentPageChanged?.Invoke(this, CurrentPage);
    }

    public Page? CurrentPage { get; private set; }
    public event EventHandler<Page?>? CurrentPageChanged;

    // ... 其他方法
}

// 注册
services.AddSingleton<INavigationService, NavigationService>();
```

### 2. 对话框服务（IDialogService）

```csharp
// 接口定义
public interface IDialogService
{
    void ShowMessage(string title, string message);
    bool ShowConfirmation(string title, string message);
    string? ShowOpenFileDialog(string filter);
    string? ShowSaveFileDialog(string filter);
}

// 实现
public class DialogService : IDialogService
{
    public void ShowMessage(string title, string message)
    {
        MessageBox.Show(message, title, MessageBoxButton.OK, MessageBoxImage.Information);
    }

    public bool ShowConfirmation(string title, string message)
    {
        var result = MessageBox.Show(message, title, MessageBoxButton.YesNo, MessageBoxImage.Question);
        return result == MessageBoxResult.Yes;
    }

    public string? ShowOpenFileDialog(string filter)
    {
        var dialog = new OpenFileDialog { Filter = filter };
        return dialog.ShowDialog() == true ? dialog.FileName : null;
    }

    public string? ShowSaveFileDialog(string filter)
    {
        var dialog = new SaveFileDialog { Filter = filter };
        return dialog.ShowDialog() == true ? dialog.FileName : null;
    }
}

// 使用
public class MyViewModel
{
    private readonly IDialogService _dialogService;

    public MyViewModel(IDialogService dialogService)
    {
        _dialogService = dialogService;
    }

    [RelayCommand]
    private void Save()
    {
        // 显示确认对话框
        if (_dialogService.ShowConfirmation("确认", "确定要保存吗？"))
        {
            // 保存逻辑...
            _dialogService.ShowMessage("成功", "保存成功！");
        }
    }
}
```

```csharp
    private void SaveToFile(string path) { /* ... */ }
}

services.AddSingleton<IConfiguration, Configuration>();
```

## 最佳实践

### 1. 面向接口编程

```csharp
// ✅ 正确：依赖接口
public class MyViewModel
{
    private readonly INavigationService _navigationService;

    public MyViewModel(INavigationService navigationService)
    {
        _navigationService = navigationService;
    }
}

// ❌ 错误：依赖具体类
public class MyViewModel
{
    private readonly NavigationService _navigationService;

    public MyViewModel(NavigationService navigationService)
    {
        _navigationService = navigationService;
    }
}
```

### 2. 构造函数注入

```csharp
// ✅ 推荐：构造函数注入
public class MyViewModel
{
    private readonly IUserService _userService;

    public MyViewModel(IUserService userService)
    {
        _userService = userService ?? throw new ArgumentNullException(nameof(userService));
    }
}

// ❌ 不推荐：属性注入
public class MyViewModel
{
    public IUserService UserService { get; set; }  // 可能为 null
}
```

### 3. 避免服务定位器（Service Locator）

```csharp
// ❌ 反模式：服务定位器
public class MyViewModel
{
    public void DoSomething()
    {
        var service = ServiceLocator.GetService<IUserService>();  // 不推荐
        service.DoWork();
    }
}

// ✅ 正确：依赖注入
public class MyViewModel
{
    private readonly IUserService _userService;

    public MyViewModel(IUserService userService)
    {
        _userService = userService;
    }

    public void DoSomething()
    {
        _userService.DoWork();
    }
}
```

### 4. 显式依赖

```csharp
// ✅ 好：依赖一目了然
public class MyViewModel
{
    public MyViewModel(
        INavigationService navigationService,
        IUserService userService,
        IDialogService dialogService)
    {
        // 清楚地知道这个类依赖什么
    }
}

// ❌ 差：隐藏的依赖
public class MyViewModel
{
    public void DoSomething()
    {
        var service = new UserService();  // 隐藏的依赖
    }
}
```

### 5. 不要过度注入

```csharp
// ❌ 过度注入（依赖太多）
public class MyViewModel
{
    public MyViewModel(
        IService1 s1, IService2 s2, IService3 s3,
        IService4 s4, IService5 s5, IService6 s6,
        IService7 s7, IService8 s8)  // 太多依赖！
    {
        // 这是一个信号：类承担了太多责任
        // 应该考虑拆分或使用门面模式（Facade）
    }
}

// ✅ 合理的依赖数量（3-5 个）
public class MyViewModel
{
    public MyViewModel(
        INavigationService navigationService,
        IUserService userService,
        IDialogService dialogService)
    {
        // 清晰合理
    }
}
```

### 面试要点

**Q1：什么是依赖注入？有什么好处？**

A：依赖注入是一种设计模式，通过外部提供依赖而不是在类内部创建。好处包括：降低耦合、提高可测试性、易于替换实现、符合开闭原则。

**Q2：Singleton 和 Transient 有什么区别？**

A：Singleton 是全局唯一实例，应用启动时创建，适用于无状态服务。Transient 是每次请求都创建新实例，适用于 ViewModel 等需要独立状态的对象。

**Q3：为什么 ViewModel 要注册为 Transient？**

A：因为每个页面需要独立的 ViewModel 实例，保持各自的状态。如果注册为 Singleton，所有页面会共享同一个 ViewModel，导致状态混乱。

**Q4：为什么 NavigationService 要注册为 Singleton？**

A：因为导航服务需要管理全局的导航状态（当前页面、历史栈等），应该在整个应用中共享同一个实例。
