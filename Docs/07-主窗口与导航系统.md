## 1. 主窗口架构总览

### 1.1 主窗口的角色

主窗口（MainWindow）是整个应用程序的**容器**和**骨架**：

```
┌────────────────────────────────────────────────┐
│         MainWindow（主窗口）                    │
├────────────────────────────────────────────────┤
│ ┌──────────┐  ┌────────────────────────────┐  │
│ │          │  │   Frame（内容容器）         │  │
│ │  左侧    │  │  ┌────────────────────┐    │  │
│ │  导航栏  │  │  │  HomePageA         │    │  │
│ │          │  │  │  或 HomePageB      │←──┼──┼─ 导航切换
│ │  MagicBar│  │  │  或 Data           │    │  │
│ │          │  │  │  或 Edit ...       │    │  │
│ │          │  │  └────────────────────┘    │  │
│ └──────────┘  └────────────────────────────┘  │
└────────────────────────────────────────────────┘
         │                       ▲
         │                       │
         └───── NavigationService ─┘
               （导航服务）
```

**主窗口不负责具体业务逻辑**，只负责：
1. 提供布局框架（左侧导航 + 右侧内容）
2. 承载导航控件（MagicBar选项卡）
3. 提供Frame容器显示不同页面
4. 协调导航服务完成页面切换

## 2. 导航服务接口设计

### 2.1 INavigationService 接口定义

**文件位置**：`Services/Navigation/INavigationService.cs`

```csharp
public interface INavigationService
{
    // 导航到指定页面
    void NavigateTo(string pageKey, object? parameter = null);

    // 返回上一页
    bool GoBack();

    // 清空导航历史
    void ClearHistory();

    // 当前页面（只读属性）
    Page? CurrentPage { get; }

    // 当前页面变化事件
    event EventHandler<Page?>? CurrentPageChanged;
}
```

### 2.2 为什么要定义接口？

**问题**：为什么不直接用 `NavigationService` 类，而要先定义一个接口？

**答案**：这是**面向接口编程**的设计原则。

**优势**：

**1️⃣ 解耦（Decoupling）**

```csharp
// ❌ 坏的做法：直接依赖具体类
public class MainWindowViewModel
{
    private NavigationService _navigationService;  // 强耦合

    public MainWindowViewModel()
    {
        _navigationService = new NavigationService();  // 直接创建
    }
}

// ✅ 好的做法：依赖接口
public class MainWindowViewModel
{
    private INavigationService _navigationService;  // 弱耦合

    public MainWindowViewModel(INavigationService navigationService)
    {
        _navigationService = navigationService;  // 通过构造函数注入
    }
}
```

**2️⃣ 可测试性（Testability）**

```csharp
// 单元测试时，可以用Mock对象替代真实的NavigationService
public class MockNavigationService : INavigationService
{
    public void NavigateTo(string pageKey, object parameter = null)
    {
        // 测试用的假实现，不会真的创建页面
        Console.WriteLine($"Mock: 导航到 {pageKey}");
    }

    // ... 实现其他接口成员
}

// 测试代码
[Test]
public void TestNavigate()
{
    var mockNav = new MockNavigationService();
    var viewModel = new MainWindowViewModel(mockNav);
    viewModel.NavigateCommand.Execute("HomePageA");
    // 验证导航是否被调用
}
```

**3️⃣ 可替换性（Substitutability）**

将来可以轻松替换导航服务的实现：
- `NavigationService` - 标准导航（当前使用）
- `StackNavigationService` - 堆栈式导航（带动画）
- `TabNavigationService` - 选项卡式导航
- 只需实现 `INavigationService` 接口即可

### 2.3 接口成员详解

| 成员 | 类型 | 作用 | 示例 |
|------|------|------|------|
| `NavigateTo(pageKey, parameter)` | 方法 | 导航到指定页面 | `NavigateTo("HomePageA")` |
| `GoBack()` | 方法 | 返回上一页 | `GoBack()` |
| `ClearHistory()` | 方法 | 清空导航历史 | `ClearHistory()` |
| `CurrentPage` | 属性 | 获取当前显示的页面 | `var page = CurrentPage;` |
| `CurrentPageChanged` | 事件 | 当前页面变化时触发 | `CurrentPageChanged += OnPageChanged;` |

## 3. 导航服务实现详解

### 3.1 NavigationService 类结构

**文件位置**：`Services/Navigation/NavigationService.cs`

```csharp
public class NavigationService : INavigationService
{
    // 1️⃣ 依赖注入容器（用于创建页面实例）
    private readonly IServiceProvider _serviceProvider;

    // 2️⃣ 页面注册表（页面键名 → 页面类型）
    private readonly Dictionary<string, Type> _pageTypes = new();

    // 3️⃣ 导航历史栈（记录访问过的页面）
    private readonly Stack<Page> _navigationHistory = new();

    // 4️⃣ 当前显示的页面
    private Page? _currentPage;

    // 5️⃣ 当前页面属性（带事件通知）
    public Page? CurrentPage
    {
        get => _currentPage;
        private set
        {
            _currentPage = value;
            CurrentPageChanged?.Invoke(this, value);  // 触发事件
        }
    }

    // 6️⃣ 当前页面变化事件
    public event EventHandler<Page?>? CurrentPageChanged;

    // ... 方法实现
}
```

**零基础讲解**：

**1️⃣ IServiceProvider 是什么？**

`IServiceProvider` 是 .NET 依赖注入（DI）容器的接口。

**作用**：从容器中获取已注册的服务实例。

```csharp
// 在 App.xaml.cs 中注册服务
services.AddTransient<HomePageA>();
services.AddTransient<HomePageB>();

// 在 NavigationService 中获取服务
var page = _serviceProvider.GetRequiredService<HomePageA>();
```

**2️⃣ Dictionary<string, Type> 是什么？**

字典（键值对集合），这里用来存储页面映射：

```csharp
// 键（string）      值（Type）
"HomePageA"    →   typeof(Views.HomePageA)
"HomePageB"    →   typeof(Views.HomePageB)
"Data"         →   typeof(Views.Data)
```

**Type** 是 C# 中的**类型对象**，代表一个类的元数据。

```csharp
Type pageType = typeof(HomePageA);
string name = pageType.Name;  // "HomePageA"
var page = Activator.CreateInstance(pageType);  // 创建实例
```

**3️⃣ Stack<Page> 导航历史栈**

**Stack**（栈）是后进先出（LIFO）的数据结构：

```
导航流程：A → B → C
                ┌───┐
Stack:          │ C │  ← Top（栈顶）
                ├───┤
                │ B │
                ├───┤
                │ A │
                └───┘

后退操作：
Pop() → 取出 C，当前页面变为 B
```

**4️⃣ private set 是什么意思？**

```csharp
public Page? CurrentPage
{
    get => _currentPage;        // 公开可读（外部可以读取）
    private set { ... }         // 私有可写（只有类内部可以修改）
}
```

外部代码只能读取，不能修改：
```csharp
// 外部代码
var page = navigationService.CurrentPage;  // ✅ 可以读取
navigationService.CurrentPage = newPage;   // ❌ 编译错误，不能修改
```

**5️⃣ `?.` 和 `?` 操作符**

```csharp
CurrentPageChanged?.Invoke(this, value);
```

- `CurrentPageChanged?` - 空值条件运算符，如果事件为 `null` 则不调用
- `Page?` - 可空引用类型，表示可以是 `null`

等价于：
```csharp
if (CurrentPageChanged != null)
{
    CurrentPageChanged.Invoke(this, value);
}
```

### 3.2 页面注册（RegisterPages 方法）

```csharp
private void RegisterPages()
{
    // 注册页面类型映射
    _pageTypes.Add("HomePageA", typeof(Views.HomePageA));
    _pageTypes.Add("HomePageB", typeof(Views.HomePageB));
    _pageTypes.Add("HomePageC", typeof(Views.HomePageC));
    _pageTypes.Add("MainMenu", typeof(Views.HomePageB));  // 别名
    _pageTypes.Add("EquipmentInfo", typeof(Views.EquipmentInfo));
    _pageTypes.Add("ReservationList", typeof(Views.ReservationList));
    _pageTypes.Add("FaultReport", typeof(Views.FaultReport));
    _pageTypes.Add("Data", typeof(Views.Data));
    _pageTypes.Add("Edit", typeof(Views.Edit));
    _pageTypes.Add("TimeSlotEdit", typeof(Views.TimeSlotEdit));
    _pageTypes.Add("FaultEdit", typeof(Views.FaultEdit));
}
```

**为什么要注册？**

将字符串键名映射到类型，实现**通过字符串导航**：

```csharp
// 不注册的话，必须这样写（硬编码）
if (pageKey == "HomePageA")
{
    page = new HomePageA();
}
else if (pageKey == "HomePageB")
{
    page = new HomePageB();
}
// ... 很多 if-else

// 注册后，简洁优雅
var pageType = _pageTypes[pageKey];  // 从字典取出类型
var page = _serviceProvider.GetRequiredService(pageType);  // 创建实例
```

**别名的妙用**：
```csharp
_pageTypes.Add("MainMenu", typeof(Views.HomePageB));
```

- "MainMenu" 和 "HomePageB" 都指向同一个页面
- 语义更清晰：导航到"主菜单"而不是"主页B"

### 3.3 NavigateTo 核心导航方法

```csharp
public void NavigateTo(string pageKey, object? parameter = null)
{
    // 1️⃣ 从字典中查找页面类型
    if (!_pageTypes.TryGetValue(pageKey, out var pageType))
    {
        throw new ArgumentException($"页面 '{pageKey}' 未注册", nameof(pageKey));
    }

    // 2️⃣ 使用DI容器创建页面实例
    var page = (Page)_serviceProvider.GetRequiredService(pageType);

    // 3️⃣ 如果ViewModel实现了INavigationAware，传递参数
    if (page.DataContext is INavigationAware navigationAware)
    {
        navigationAware.OnNavigatedTo(parameter);
    }

    // 4️⃣ 保存当前页面到历史栈
    if (CurrentPage != null)
    {
        _navigationHistory.Push(CurrentPage);
    }

    // 5️⃣ 更新当前页面（触发CurrentPageChanged事件）
    CurrentPage = page;
}
```

**逐步详解**：

**步骤1：查找页面类型**

```csharp
if (!_pageTypes.TryGetValue(pageKey, out var pageType))
{
    throw new ArgumentException($"页面 '{pageKey}' 未注册", nameof(pageKey));
}
```

**TryGetValue 方法**：
- 尝试从字典中获取值
- 如果键存在，返回 `true` 并将值赋给 `out` 参数
- 如果键不存在，返回 `false`

```csharp
// 示例
Dictionary<string, Type> dict = new()
{
    { "A", typeof(int) },
    { "B", typeof(string) }
};

if (dict.TryGetValue("A", out var type))
{
    Console.WriteLine(type);  // 输出: System.Int32
}

if (!dict.TryGetValue("C", out var type2))
{
    Console.WriteLine("键 'C' 不存在");  // 会执行这里
}
```

**throw new ArgumentException**：
- 抛出异常（程序出错）
- `ArgumentException` - 参数异常类型
- `$"页面 '{pageKey}' 未注册"` - 错误消息
- `nameof(pageKey)` - 参数名称

**步骤2：创建页面实例（依赖注入）**

```csharp
var page = (Page)_serviceProvider.GetRequiredService(pageType);
```

**GetRequiredService 做了什么？**

假设我们导航到 "HomePageA"：

```csharp
// pageType = typeof(HomePageA)

// HomePageA 的构造函数：
public HomePageA(HomePageAViewModel viewModel)
{
    DataContext = viewModel;
    InitializeComponent();
}

// DI容器会：
// 1. 检查 HomePageA 的构造函数需要 HomePageAViewModel
// 2. 创建 HomePageAViewModel 实例
// 3. 注入到构造函数中
// 4. 返回完整的 HomePageA 实例
```

等价于手动创建：
```csharp
var viewModel = new HomePageAViewModel();
var page = new HomePageA(viewModel);
```

**类型转换**：
```csharp
(Page)_serviceProvider.GetRequiredService(pageType)
```

- `GetRequiredService` 返回 `object` 类型
- 强制转换为 `Page` 类型
- 因为我们知道注册的都是 `Page` 的子类

**步骤3：传递导航参数（INavigationAware）**

```csharp
if (page.DataContext is INavigationAware navigationAware)
{
    navigationAware.OnNavigatedTo(parameter);
}
```

**INavigationAware 接口**：

```csharp
public interface INavigationAware
{
    void OnNavigatedTo(object? parameter);   // 导航到此页面时调用
    void OnNavigatedFrom();                  // 离开此页面时调用
}
```

**使用场景**：

```csharp
// 导航时传递参数
_navigationService.NavigateTo("Data", "2024");  // 传递年份参数

// DataViewModel 实现 INavigationAware
public class DataViewModel : ViewModelBase, INavigationAware
{
    public void OnNavigatedTo(object? parameter)
    {
        if (parameter is string year)
        {
            SelectedYear = year;  // 设置选中的年份
            LoadData(year);       // 加载该年份的数据
        }
    }

    public void OnNavigatedFrom()
    {
        // 离开页面时的清理工作
    }
}
```

**is 模式匹配**：

```csharp
if (page.DataContext is INavigationAware navigationAware)
```

等价于：
```csharp
if (page.DataContext is INavigationAware)
{
    var navigationAware = (INavigationAware)page.DataContext;
    // 使用 navigationAware
}
```

现代写法更简洁，一步完成类型检查和转换。

**步骤4：保存导航历史**

```csharp
if (CurrentPage != null)
{
    _navigationHistory.Push(CurrentPage);
}
```

**Stack.Push 方法**：将元素压入栈顶

```
初始状态: CurrentPage = PageA
导航到 PageB:

1. Push(PageA) → 将 PageA 压入栈
   Stack: [PageA]

2. CurrentPage = PageB → 更新当前页面

导航到 PageC:

1. Push(PageB) → 将 PageB 压入栈
   Stack: [PageA, PageB]

2. CurrentPage = PageC → 更新当前页面
```

**步骤5：更新当前页面并触发事件**

```csharp
CurrentPage = page;
```

触发属性的 `set` 访问器：

```csharp
public Page? CurrentPage
{
    get => _currentPage;
    private set
    {
        _currentPage = value;  // 更新字段
        CurrentPageChanged?.Invoke(this, value);  // 触发事件
    }
}
```

**事件触发后谁会收到通知？**

在 `MainWindow.xaml.cs` 中订阅了这个事件：

```csharp
// MainWindow.xaml.cs
public MainWindow(MainWindowViewModel viewModel, INavigationService navigationService)
{
    InitializeComponent();
    DataContext = viewModel;
    _navigationService = navigationService;

    // 订阅事件
    _navigationService.CurrentPageChanged += OnCurrentPageChanged;
}

private void OnCurrentPageChanged(object? sender, Page? page)
{
    // 更新Frame的内容
    if (MainContentFrame != null)
    {
        MainContentFrame.Content = page;  // 显示新页面
    }
}
```

**完整流程图**：

```
用户操作                   ViewModel                NavigationService         MainWindow
   │                          │                           │                        │
   │  点击导航按钮             │                           │                        │
   │─────────────────────────>│                           │                        │
   │                          │  NavigateCommand.Execute()│                        │
   │                          │──────────────────────────>│                        │
   │                          │                           │ 查找页面类型            │
   │                          │                           │ 创建页面实例（DI）      │
   │                          │                           │ 传递导航参数            │
   │                          │                           │ Push旧页面到栈          │
   │                          │                           │ CurrentPage = 新页面   │
   │                          │                           │──────────────────────>│
   │                          │                           │ CurrentPageChanged事件 │
   │                          │                           │                        │
   │                          │                           │                        │ Frame.Content = page
   │  看到新页面               │                           │                        │
   │<═══════════════════════════════════════════════════════════════════════════════│
```

### 3.4 GoBack 返回上一页

```csharp
public bool GoBack()
{
    // 1️⃣ 检查导航历史是否为空
    if (_navigationHistory.Count == 0)
        return false;  // 已经在第一页，无法返回

    // 2️⃣ 从栈中取出上一页
    CurrentPage = _navigationHistory.Pop();

    return true;  // 返回成功
}
```

**Stack.Pop 方法**：弹出栈顶元素

```
导航历史: [PageA, PageB]  CurrentPage = PageC

GoBack():
1. Pop() → 返回 PageB，栈变为 [PageA]
2. CurrentPage = PageB

再次 GoBack():
1. Pop() → 返回 PageA，栈变为 []
2. CurrentPage = PageA

再次 GoBack():
1. Count == 0 → 返回 false，无法继续后退
```

## 4. MainWindowViewModel 完整解析

### 4.1 依赖注入与初始化

```csharp
public partial class MainWindowViewModel : ViewModelBase
{
    private readonly INavigationService _navigationService;

    public MainWindowViewModel(INavigationService navigationService)
    {
        _navigationService = navigationService;

        // 1️⃣ 监听导航变化，更新UI状态
        _navigationService.CurrentPageChanged += OnCurrentPageChanged;

        // 2️⃣ 订阅页面切换消息
        WeakReferenceMessenger.Default.Register<ChangePageMessage>(this, (recipient, message) =>
        {
            if (!string.IsNullOrEmpty(message.PageKey))
            {
                _navigationService.NavigateTo(message.PageKey, message.Parameter);
            }
        });

        // 3️⃣ 初始化年份月份数据
        InitializeMonthsAndYears();

        // 4️⃣ 导航到默认页面
        _navigationService.NavigateTo("HomePageB");
    }
}
```

**构造函数注入**：

```csharp
public MainWindowViewModel(INavigationService navigationService)
{
    _navigationService = navigationService;
}
```

- 参数 `INavigationService navigationService` 由 DI 容器自动提供
- 不需要手动 `new NavigationService()`

**在 App.xaml.cs 中的注册**：

```csharp
services.AddSingleton<INavigationService, NavigationService>();
services.AddTransient<MainWindowViewModel>();
```

**Singleton vs Transient**：

| 生命周期 | 说明 | 适用场景 |
|----------|------|---------|
| Singleton | 整个应用只有一个实例 | 导航服务、配置服务、数据缓存 |
| Transient | 每次请求都创建新实例 | ViewModel、短生命周期对象 |
| Scoped | 在一个作用域内是同一个实例 | Web应用的请求作用域 |

**NavigationService 为什么用 Singleton？**
- 导航状态需要全局共享
- 导航历史栈需要持久保存
- 避免重复创建，节省资源

### 4.3 OnCurrentPageChanged 事件处理

```csharp
private void OnCurrentPageChanged(object? sender, System.Windows.Controls.Page? page)
{
    // 1️⃣ 更新CurrentPage属性（绑定到UI）
    CurrentPage = page;

    if (page == null) return;

    // 2️⃣ 根据页面类型更新按钮可见性
    var pageType = page.GetType();
    bool shouldShowButtons = pageType.Name is "HomePageA" or "HomePageB" or "HomePageC";

    IsButton1Visible = shouldShowButtons;
    IsButton2Visible = shouldShowButtons;

    // 3️⃣ 根据页面类型更新MagicBar可见性
    bool shouldShowMagicBar = pageType.Name is "Edit" or "TimeSlotEdit" or "FaultEdit";
    IsMagicBarVisible = shouldShowMagicBar;

    // 4️⃣ 调整Frame的Margin
    FrameMargin = shouldShowMagicBar
        ? new Thickness(20, 20, 20, 90)
        : new Thickness(30, 30, 30, 50);

    // 5️⃣ 更新MagicBar选中索引
    MagicBarSelectedIndex = pageType.Name switch
    {
        "Edit" => 0,
        "TimeSlotEdit" => 1,
        "FaultEdit" => 2,
        _ => -1
    };
}
```

**零基础讲解**：

**1️⃣ `page.GetType()` 获取类型**

```csharp
var pageType = page.GetType();
string typeName = pageType.Name;  // "HomePageA", "Edit" 等
```

**2️⃣ `is` 模式匹配（多值）**

```csharp
pageType.Name is "HomePageA" or "HomePageB" or "HomePageC"
```

等价于：
```csharp
pageType.Name == "HomePageA" ||
pageType.Name == "HomePageB" ||
pageType.Name == "HomePageC"
```

现代写法更简洁。

**3️⃣ `switch` 表达式**

```csharp
MagicBarSelectedIndex = pageType.Name switch
{
    "Edit" => 0,
    "TimeSlotEdit" => 1,
    "FaultEdit" => 2,
    _ => -1  // 下划线表示"其他所有情况"
};
```

等价于传统 `switch` 语句：
```csharp
switch (pageType.Name)
{
    case "Edit":
        MagicBarSelectedIndex = 0;
        break;
    case "TimeSlotEdit":
        MagicBarSelectedIndex = 1;
        break;
    case "FaultEdit":
        MagicBarSelectedIndex = 2;
        break;
    default:
        MagicBarSelectedIndex = -1;
        break;
}
```

**4️⃣ 三元运算符**

```csharp
FrameMargin = shouldShowMagicBar
    ? new Thickness(20, 20, 20, 90)
    : new Thickness(30, 30, 30, 50);
```

等价于：
```csharp
if (shouldShowMagicBar)
{
    FrameMargin = new Thickness(20, 20, 20, 90);
}
else
{
    FrameMargin = new Thickness(30, 30, 30, 50);
}
```

**Thickness 是什么？**

WPF 中表示四个方向的边距：

```csharp
new Thickness(左, 上, 右, 下)
new Thickness(30, 30, 30, 50)  // 左右上边距30，下边距50
```

### 4.5 消息传递机制

```csharp
// 订阅页面切换消息
WeakReferenceMessenger.Default.Register<ChangePageMessage>(this, (recipient, message) =>
{
    if (!string.IsNullOrEmpty(message.PageKey))
    {
        _navigationService.NavigateTo(message.PageKey, message.Parameter);
    }
});
```

**WeakReferenceMessenger 是什么？**

来自 `CommunityToolkit.Mvvm`，用于解耦的消息传递机制。

**使用场景**：

```csharp
// 在 EquipmentInfoViewModel 中发送消息
WeakReferenceMessenger.Default.Send(new ChangePageMessage("Edit"));

// MainWindowViewModel 收到消息后导航到 Edit 页面
_navigationService.NavigateTo("Edit");
```

**为什么叫 WeakReference（弱引用）？**

- 防止内存泄漏
- 订阅者被垃圾回收后，消息系统会自动取消订阅
- 不需要手动 `Unregister`（但最好还是手动取消）

**ChangePageMessage 定义**：

```csharp
// Messages/ChangePageMessage.cs
public class ChangePageMessage
{
    public string PageKey { get; set; }
    public object? Parameter { get; set; }

    public ChangePageMessage(string pageKey, object? parameter = null)
    {
        PageKey = pageKey;
        Parameter = parameter;
    }
}
```

## 8. 面试要点 ⭐

1. **导航服务的设计原则**
   - 单一职责：只负责导航逻辑
   - 接口隔离：通过接口解耦
   - 依赖倒置：依赖抽象而非具体类

2. **为什么用字符串键名而不是类型？**
   - 灵活性：可以在XAML中绑定
   - 可配置：可以从配置文件读取
   - 解耦：不需要引用具体的View类型

3. **导航历史的实现**
   - 使用栈（Stack）存储历史
   - 后进先出（LIFO）特性适合后退操作

4. **依赖注入的优势**
   - 自动解决依赖关系
   - 生命周期管理
   - 提高可测试性
