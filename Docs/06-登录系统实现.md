## 1. 登录系统整体架构

### 1.1 登录功能的组成部分

登录系统由以下三个文件组成：

```
登录系统
├── Login.xaml          # 界面定义（UI层）- 用户看到的界面
├── Login.xaml.cs       # 界面代码后台（事件处理）
└── LoginViewModel.cs   # 业务逻辑（ViewModel层）- 登录验证逻辑
```

**职责划分**：
- **Login.xaml**：纯UI，定义界面长什么样（按钮、文本框的位置、颜色、大小等）
- **Login.xaml.cs**：处理一些必须在代码中处理的事件（如窗口拖动、密码框处理）
- **LoginViewModel.cs**：所有业务逻辑（验证用户名密码、跳转主窗口等）

### 1.2 MVVM模式在登录中的体现

```
View (Login.xaml)
    ↕️ 数据绑定 (Binding)
ViewModel (LoginViewModel.cs)
    ↕️ 数据传递
Model (LoginModel.cs) - 本项目中较简单，未单独创建
```

**数据流向**：
1. 用户在界面输入用户名 → 自动更新到 `ViewModel.Username` 属性
2. 用户输入密码 → 手动更新到 `ViewModel.Password` 属性（密码框特殊处理）
3. 用户点击"登录"按钮 → 触发 `ViewModel.LoginCommand` 命令
4. ViewModel 验证成功 → 打开主窗口，关闭登录窗口

## 2. Login.xaml 界面详细解析

### 2.1 窗口基本属性（第1-16行）

```xml
<Window x:Class="DataVisualizationPlatform.Views.Login"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:vm="clr-namespace:DataVisualizationPlatform.ViewModels"
        Height="800"
        Width="600"
        WindowStartupLocation="CenterScreen"
        WindowStyle="None"
        AllowsTransparency="True"
        Background="Transparent"
        ResizeMode="NoResize">
```

**逐行解释**（假设你是零基础）：

| 代码 | 含义 | 为什么这样写 |
|------|------|-------------|
| `x:Class="..."` | 这个XAML文件对应的C#类名 | 告诉WPF这个界面对应哪个后台代码文件 |
| `xmlns="..."` | WPF默认命名空间 | 引入基础控件（Button、TextBox等） |
| `xmlns:x="..."` | XAML语言命名空间 | 提供XAML特有的功能（如x:Name） |
| `xmlns:vm="..."` | 引入ViewModel命名空间 | 让我们可以在XAML中使用LoginViewModel |
| `Height="800" Width="600"` | 窗口大小 | 固定窗口为 800px高 × 600px宽 |
| `WindowStartupLocation="CenterScreen"` | 窗口启动位置 | 窗口显示在屏幕正中央 |
| `WindowStyle="None"` | 窗口样式 | 隐藏默认的标题栏和边框（自定义窗口） |
| `AllowsTransparency="True"` | 允许透明 | 实现圆角边框效果（需要配合Background="Transparent"） |
| `ResizeMode="NoResize"` | 不允许调整大小 | 用户无法拖动边框改变窗口大小 |

**为什么要隐藏标题栏？**
- 默认的Windows标题栏样式很丑，不符合现代化设计
- 我们想要自己设计一个漂亮的登录界面
- 代价是需要自己实现关闭按钮、拖动等功能

### 2.2 设置 DataContext（第18-20行）

```xml
<Window.DataContext>
    <vm:LoginViewModel/>
</Window.DataContext>
```

**这三行代码非常重要！**

**什么是 DataContext？**
- DataContext 是"数据上下文"，是 WPF 数据绑定的核心
- 可以理解为：这个窗口的所有控件默认从哪里获取数据

**这里做了什么？**
```csharp
// 等价于在C#中写：
this.DataContext = new LoginViewModel();
```

**效果**：
- 窗口中的所有 `{Binding}` 表达式都会从 `LoginViewModel` 的实例中查找属性
- 例如：`{Binding Username}` 会自动绑定到 `LoginViewModel.Username` 属性

**为什么在XAML中创建而不是在C#中？**
- 纯粹是写法习惯，两种方式都可以
- 在XAML中创建更符合MVVM的"声明式"风格
- 但在大型项目中，通常用依赖注入来创建（我们后面会讲到）

### 2.3 资源字典（第22-30行）

```xml
<Window.Resources>
    <ResourceDictionary>
        <ResourceDictionary.MergedDictionaries>
            <ResourceDictionary Source="/Resources/Styles/LoginStyle.xaml"/>
        </ResourceDictionary.MergedDictionaries>

        <BooleanToVisibilityConverter x:Key="BoolToVisConverter"/>
    </ResourceDictionary>
</Window.Resources>
```

**什么是资源字典？**
- 存放可重用资源的地方（样式、颜色、转换器等）
- 类似于 CSS 中的样式表

**MergedDictionaries（合并字典）**：
```xml
<ResourceDictionary Source="/Resources/Styles/LoginStyle.xaml"/>
```
- 引入外部样式文件 `LoginStyle.xaml`
- 该文件定义了 `ModernTextBox`、`LoginButton` 等样式
- 引入后，本窗口就可以使用这些样式

**转换器（Converter）**：
```xml
<BooleanToVisibilityConverter x:Key="BoolToVisConverter"/>
```
- `BooleanToVisibilityConverter` 是 WPF 内置的转换器
- 作用：将 `bool` 类型转换为 `Visibility` 类型
  - `true` → `Visible`（可见）
  - `false` → `Collapsed`（隐藏且不占空间）
- `x:Key="BoolToVisConverter"` 给这个转换器起个名字，方便后面使用

**在哪里用到了这个转换器？**
```xml
<!-- 错误提示边框，只有HasError=true时才显示 -->
<Border Visibility="{Binding HasError, Converter={StaticResource BoolToVisConverter}}">
    <!-- 错误信息 -->
</Border>
```

### 2.4 主容器卡片（第32-44行）

```xml
<Grid>
    <!-- 主容器卡片 -->
    <Border Background="White"
            CornerRadius="16"
            MouseLeftButtonDown="Border_MouseLeftButtonDown">
```

**Border 控件**：

- `CornerRadius="16"` - 圆角半径16像素（让边框变圆）

**DropShadowEffect（阴影效果）**：
- `BlurRadius="30"` - 模糊半径（阴影有多"虚"）
- `ShadowDepth="0"` - 阴影偏移距离（0表示四周均匀阴影）
- `Opacity="0.2"` - 阴影透明度（20%不透明度）
- `Color="#000000"` - 阴影颜色（黑色）

**为什么要在Border上处理拖动？**
因为我们设置了 `WindowStyle="None"`，隐藏了默认标题栏，所以：
- 默认情况下，用户无法拖动窗口
- 我们在 `Border_MouseLeftButtonDown` 事件中调用 `DragMove()` 方法
- 效果：用户点击白色卡片任意位置都可以拖动窗口

**关键知识点1：数据绑定**

```xml
Text="{Binding Username, UpdateSourceTrigger=PropertyChanged}"
```

**拆解讲解**：
- `Text="{Binding Username}"` - 将TextBox的Text属性绑定到ViewModel的Username属性
- `UpdateSourceTrigger=PropertyChanged` - 更新时机设置

**UpdateSourceTrigger 的三种模式**：

| 模式 | 触发时机 | 适用场景 |
|------|---------|---------|
| `PropertyChanged` | 每次输入一个字符就更新 | 实时验证、搜索框 |
| `LostFocus` | 失去焦点时才更新 | 表单输入 |
| `Explicit` | 手动调用更新 | 需要精确控制的场景 |

**为什么用 PropertyChanged？**
- 用户每输入一个字符，ViewModel 中的 `Username` 就会更新
- `OnUsernameChanged` 方法会被触发，清除错误提示
- 实时反馈，用户体验更好

**关键知识点2：键盘绑定**

```xml
<TextBox.InputBindings>
    <KeyBinding Key="Return" Command="{Binding LoginCommand}"/>
</TextBox.InputBindings>
```

**作用**：
- 用户在用户名输入框按下 `Enter` 键
- 自动触发 `LoginCommand` 命令
- 效果：不用点击"登录"按钮，按Enter就能登录

**关键知识点3：图标叠加**

```xml
<Grid>
    <TextBox ... />  <!-- 文本框 -->
    <Path ... />     <!-- 用户图标 -->
</Grid>
```

- `Grid` 默认只有一个单元格
- 多个元素放在同一个 `Grid` 中会重叠显示
- `Path` 是一个用户图标（SVG路径）
- `IsHitTestVisible="False"` - 图标不响应鼠标点击（点击穿透到TextBox）

### 2.6 密码输入框（第210-235行）

```xml
<Grid Margin="0,0,0,20">
    <PasswordBox x:Name="PasswordBox"
                 Style="{StaticResource ModernPasswordBox}"
                 PasswordChanged="PasswordBox_PasswordChanged"
                 TabIndex="2">
        <PasswordBox.InputBindings>
            <KeyBinding Key="Return" Command="{Binding LoginCommand}"/>
        </PasswordBox.InputBindings>
    </PasswordBox>
    <!-- 锁图标 -->
</Grid>
```

**为什么密码框不用 Binding？**

注意：密码框没有 `Password="{Binding ...}"` 绑定！

**原因**：
- `PasswordBox.Password` 属性**不是依赖属性**（DependencyProperty）
- WPF 出于安全考虑，密码不能直接绑定
- 防止密码明文存储在内存中被恶意软件读取

**那怎么获取密码？**

通过事件：`PasswordChanged="PasswordBox_PasswordChanged"`

在 `Login.xaml.cs` 中：
```csharp
private void PasswordBox_PasswordChanged(object sender, RoutedEventArgs e)
{
    if (DataContext is LoginViewModel viewModel)
    {
        viewModel.Password = PasswordBox.Password;
    }
}
```

**流程**：
1. 用户输入密码
2. 触发 `PasswordChanged` 事件
3. 事件处理器获取密码框的 `Password` 属性
4. 手动赋值给 `ViewModel.Password`

## 3. LoginViewModel.cs 业务逻辑详解

### 3.1 类定义和继承（第8-17行）

```csharp
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;

public partial class LoginViewModel : ViewModelBase
{
    // 测试账户常量
    private const string TEST_USERNAME = "admin";
    private const string TEST_PASSWORD = "123456";
```

**关键点1：partial 关键字**

```csharp
public partial class LoginViewModel
```

**什么是 partial class（分部类）？**
- 一个类的定义可以分散在多个文件中
- 编译时会合并成一个完整的类

**为什么要用 partial？**
- `CommunityToolkit.Mvvm` 使用**源生成器**（Source Generator）
- 编译时会自动生成另一半代码（属性、命令的实现）
- 我们只需要写核心逻辑，重复代码由工具自动生成

**关键点2：继承 ViewModelBase**

```csharp
public partial class LoginViewModel : ViewModelBase
```

`ViewModelBase` 是所有ViewModel的基类，提供：
- `IsBusy` 属性（是否正在加载）
- `IsNotBusy` 属性（计算属性，= !IsBusy）
- `INotifyPropertyChanged` 接口的实现

### 3.2 属性定义（第19-29行）

```csharp
[ObservableProperty]
private string _username = string.Empty;

[ObservableProperty]
private string _password = string.Empty;

[ObservableProperty]
private bool _rememberMe;

[ObservableProperty]
private string _errorMessage = string.Empty;
```

**这是什么神奇的语法？**

`[ObservableProperty]` 是一个**特性（Attribute）**，来自 `CommunityToolkit.Mvvm`。

**它会自动生成什么代码？**

以 `_username` 为例，源生成器会自动生成：

```csharp
// 自动生成的代码（在编译时）
private string _username = string.Empty;

public string Username
{
    get => _username;
    set
    {
        if (_username != value)
        {
            OnUsernameChanging(value);  // 变化前钩子
            _username = value;
            OnPropertyChanged(nameof(Username));  // 通知UI更新
            OnUsernameChanged(value);  // 变化后钩子
        }
    }
}
```

**传统写法对比**：

不用 `[ObservableProperty]`，你需要手动写：

```csharp
private string _username = string.Empty;

public string Username
{
    get => _username;
    set
    {
        if (_username != value)
        {
            _username = value;
            OnPropertyChanged(nameof(Username));
        }
    }
}
```

**优势**：
- ✅ 代码量减少90%
- ✅ 不容易出错（忘记调用 OnPropertyChanged）
- ✅ 自动提供变化前后的钩子方法

**命名约定**：
- 私有字段：`_username`（小写，带下划线）
- 公共属性：`Username`（大写，自动生成）

### 3.3 计算属性（第31-33行）

```csharp
// 计算属性
public bool HasError => !string.IsNullOrEmpty(ErrorMessage);
public string LoginButtonText => IsBusy ? "登录中..." : "登录";
```

**什么是计算属性（Computed Property）？**
- 属性的值不是存储的，而是实时计算出来的
- 使用表达式体语法 `=>`

**HasError 的工作原理**：

```csharp
public bool HasError => !string.IsNullOrEmpty(ErrorMessage);
```

- 等价于：`HasError = (ErrorMessage不为空)`
- `ErrorMessage = ""` → `HasError = false`
- `ErrorMessage = "用户名或密码错误"` → `HasError = true`

**为什么不用 [ObservableProperty]？**
- 计算属性的值依赖其他属性（`ErrorMessage`）
- 不需要单独存储
- 当 `ErrorMessage` 变化时，手动通知 `HasError` 更新

### 3.4 构造函数（第35-45行）

```csharp
public LoginViewModel()
{
    // 订阅IsBusy属性变化，通知LoginButtonText更新
    PropertyChanged += (s, e) =>
    {
        if (e.PropertyName == nameof(IsBusy))
        {
            OnPropertyChanged(nameof(LoginButtonText));
        }
    };
}
```

**这段代码在做什么？**

监听 `IsBusy` 属性的变化，同时更新 `LoginButtonText`。

**为什么需要这样做？**

因为 `LoginButtonText` 是计算属性，依赖于 `IsBusy`：

```csharp
public string LoginButtonText => IsBusy ? "登录中..." : "登录";
```

**流程**：
1. `IsBusy` 从 `false` 变为 `true`
2. 触发 `PropertyChanged` 事件
3. 构造函数中的事件处理器被调用
4. 手动调用 `OnPropertyChanged(nameof(LoginButtonText))`
5. UI 重新读取 `LoginButtonText`，按钮文字从"登录"变为"登录中..."

**Lambda 表达式语法**：
```csharp
PropertyChanged += (s, e) => { ... };
```
- `(s, e)` - 参数：s = sender（事件发送者），e = 事件参数
- `=>` - Lambda箭头
- `{ ... }` - 方法体

等价于：
```csharp
PropertyChanged += OnPropertyChangedHandler;

private void OnPropertyChangedHandler(object sender, PropertyChangedEventArgs e)
{
    if (e.PropertyName == nameof(IsBusy))
    {
        OnPropertyChanged(nameof(LoginButtonText));
    }
}
```

### 3.5 属性变化钩子（第47-61行）

```csharp
// 属性变化时清除错误信息
partial void OnUsernameChanged(string value)
{
    ErrorMessage = string.Empty;
}

partial void OnPasswordChanged(string value)
{
    ErrorMessage = string.Empty;
}

partial void OnErrorMessageChanged(string value)
{
    OnPropertyChanged(nameof(HasError));
}
```

**partial void 是什么？**

- `partial void` 是**分部方法**
- 源生成器会在自动生成的代码中调用这些方法
- 我们只需要实现方法体，调用时机由生成器负责

**OnUsernameChanged 何时被调用？**

当 `Username` 属性的值改变后：

```csharp
// 自动生成的代码
public string Username
{
    set
    {
        _username = value;
        OnPropertyChanged(nameof(Username));
        OnUsernameChanged(value);  // 👈 在这里调用！
    }
}
```

**为什么用户名变化时要清空错误信息？**

用户体验优化：
1. 用户输入错误的用户名密码
2. 显示错误提示："用户名或密码错误"
3. 用户修改用户名
4. 立即清除错误提示（让用户知道可以重新尝试）

**OnErrorMessageChanged 的作用**：

```csharp
partial void OnErrorMessageChanged(string value)
{
    OnPropertyChanged(nameof(HasError));
}
```

- `ErrorMessage` 变化时，通知 `HasError` 也变化了
- `HasError` 是计算属性，依赖 `ErrorMessage`
- UI 中绑定了 `HasError` 的错误提示框会自动显示/隐藏

### 3.6 登录命令（第63-120行）⭐⭐⭐ 核心逻辑

```csharp
[RelayCommand(CanExecute = nameof(CanLogin))]
private async Task LoginAsync()
{
    // ... 登录逻辑
}

private bool CanLogin() => !IsBusy;
```

**[RelayCommand] 特性**：

自动生成 `ICommand` 接口的实现。

**生成的代码**：
```csharp
// 自动生成
public ICommand LoginCommand { get; }

// 构造函数中初始化
LoginCommand = new AsyncRelayCommand(LoginAsync, CanLogin);
```

**CanExecute 参数**：
- `CanExecute = nameof(CanLogin)` 指定命令的可执行条件
- `CanLogin()` 返回 `false` 时，命令禁用（按钮变灰）
- `IsBusy = true` 时，`CanLogin()` 返回 `false`，按钮禁用

**async Task 异步方法**：

```csharp
private async Task LoginAsync()
```

- `async` - 异步方法修饰符
- `Task` - 返回类型（异步操作）
- `await` - 等待异步操作完成

**登录逻辑详解**：

```csharp
[RelayCommand(CanExecute = nameof(CanLogin))]
private async Task LoginAsync()
{
    ErrorMessage = string.Empty;  // 清空之前的错误

    // 1️⃣ 验证用户名
    if (string.IsNullOrWhiteSpace(Username))
    {
        ErrorMessage = "请输入用户名";
        return;  // 提前返回，不继续执行
    }

    // 2️⃣ 验证密码
    if (string.IsNullOrWhiteSpace(Password))
    {
        ErrorMessage = "请输入密码";
        return;
    }

    // 3️⃣ 验证账号密码
    if (Username.Trim() != TEST_USERNAME || Password != TEST_PASSWORD)
    {
        // 账号密码错误，直接显示错误，不显示遮罩
        ErrorMessage = "用户名或密码错误";
        return;
    }

    // 4️⃣ 账号密码正确，显示遮罩并模拟加载过程
    IsBusy = true;  // 显示"正在登录..."遮罩

    try
    {
        // 模拟网络请求（例如：调用API验证token）
        await Task.Delay(1500); // 等待1.5秒

        // 5️⃣ 登录成功，打开主窗口
        var mainWindow = App.GetService<MainWindow>();
        mainWindow.Show();

        // 6️⃣ 关闭登录窗口
        var loginWindow = Application.Current.Windows
            .OfType<Login>()
            .FirstOrDefault();
        loginWindow?.Close();
    }
    catch (Exception ex)
    {
        // 7️⃣ 异常处理
        ErrorMessage = "登录失败，请稍后重试";
        System.Diagnostics.Debug.WriteLine($"登录异常: {ex}");
    }
    finally
    {
        // 8️⃣ 无论成功失败，都隐藏遮罩
        IsBusy = false;
    }
}
```

**逐步详解**：

**步骤1-3：输入验证**

```csharp
if (string.IsNullOrWhiteSpace(Username))
{
    ErrorMessage = "请输入用户名";
    return;
}
```

- `string.IsNullOrWhiteSpace()` - 检查字符串是否为空或只包含空格
- 设置 `ErrorMessage` → 触发 `HasError = true` → 错误提示框显示
- `return` - 提前返回，不继续执行后面的代码

**步骤4：显示加载遮罩**

```csharp
IsBusy = true;
```

- 设置 `IsBusy = true`
- UI 中的加载遮罩绑定了 `IsBusy`，自动显示
- 按钮绑定了 `IsEnabled="{Binding IsNotLoading}"`，自动禁用

**步骤5：异步等待**

```csharp
await Task.Delay(1500);
```

- `Task.Delay(1500)` - 创建一个延迟1500毫秒（1.5秒）的任务
- `await` - 等待任务完成，期间不阻塞UI线程
- **为什么要延迟？**
  - 模拟真实的网络请求（实际项目中会调用API）
  - 让用户看到加载动画，体验更好

**步骤6：依赖注入获取主窗口**

```csharp
var mainWindow = App.GetService<MainWindow>();
mainWindow.Show();
```

**什么是 `App.GetService<MainWindow>()`？**

这是依赖注入（DI）的用法。

**在 App.xaml.cs 中已经注册**：
```csharp
services.AddTransient<MainWindow>();
```

**工作原理**：
1. `App.GetService<MainWindow>()` 向 DI 容器请求 `MainWindow` 实例
2. DI 容器检查构造函数需要哪些参数
3. 自动创建依赖对象（如 `MainWindowViewModel`、`NavigationService`）
4. 返回完整的 `MainWindow` 实例

等价于手动创建：
```csharp
var navigationService = new NavigationService();
var viewModel = new MainWindowViewModel(navigationService);
var mainWindow = new MainWindow(viewModel, navigationService);
```

**优势**：
- ✅ 自动管理依赖关系
- ✅ 不需要手动 `new` 对象
- ✅ 方便测试（可以注入Mock对象）

**步骤7：关闭登录窗口**

```csharp
var loginWindow = Application.Current.Windows
    .OfType<Login>()
    .FirstOrDefault();
loginWindow?.Close();
```

**逐行解析**：
- `Application.Current.Windows` - 获取当前应用的所有打开窗口
- `.OfType<Login>()` - 筛选出 `Login` 类型的窗口
- `.FirstOrDefault()` - 取第一个，如果没有返回 `null`
- `loginWindow?.Close()` - `?.` 是空值条件运算符，如果不为 `null` 才调用 `Close()`

**步骤8：异常处理**

```csharp
try
{
    // 可能出错的代码
}
catch (Exception ex)
{
    ErrorMessage = "登录失败，请稍后重试";
    System.Diagnostics.Debug.WriteLine($"登录异常: {ex}");
}
finally
{
    IsBusy = false;
}
```

**try-catch-finally 结构**：
- `try` - 尝试执行的代码块
- `catch (Exception ex)` - 捕获异常并处理
- `finally` - 无论成功还是失败都会执行

**为什么用 finally？**
- 确保 `IsBusy = false` 一定会执行
- 即使发生异常，加载遮罩也会关闭
- 用户不会被卡在"正在登录..."界面

## 5. 异步登录流程详解

### 5.1 async/await 原理

**什么是异步（Asynchronous）？**

同步执行：
```csharp
Console.WriteLine("开始");
Thread.Sleep(2000);  // 阻塞UI线程2秒，界面卡死
Console.WriteLine("结束");
```

异步执行：
```csharp
Console.WriteLine("开始");
await Task.Delay(2000);  // UI线程可以处理其他事情，界面不卡
Console.WriteLine("结束");
```

**async/await 的工作原理**：

```csharp
private async Task LoginAsync()
{
    IsBusy = true;                  // 1️⃣ 执行到这里
    await Task.Delay(1500);         // 2️⃣ 遇到await，释放UI线程
                                     // （UI可以处理用户点击、动画等）
                                     // 3️⃣ 1.5秒后继续执行
    var mainWindow = App.GetService<MainWindow>();  // 4️⃣ 继续执行
    mainWindow.Show();
}
```

**关键点**：
- `await` 不会阻塞 UI 线程
- UI 保持响应（用户可以看到动画、移动窗口等）
- `await` 后面的代码会在异步操作完成后继续执行

## 7. 知识点总结

### 核心概念

| 概念 | 说明 | 代码示例 |
|------|------|---------|
| **MVVM分离** | View负责UI，ViewModel负责逻辑 | `Login.xaml` + `LoginViewModel.cs` |
| **数据绑定** | UI和ViewModel属性自动同步 | `Text="{Binding Username}"` |
| **命令绑定** | 按钮点击触发ViewModel命令 | `Command="{Binding LoginCommand}"` |
| **[ObservableProperty]** | 自动生成属性和通知代码 | `[ObservableProperty] private string _username;` |
| **[RelayCommand]** | 自动生成ICommand实现 | `[RelayCommand] private async Task LoginAsync()` |
| **async/await** | 异步操作不阻塞UI | `await Task.Delay(1500);` |
| **值转换器** | 类型转换（bool→Visibility） | `Converter={StaticResource BoolToVisConverter}` |
| **依赖注入** | 自动创建和管理对象 | `App.GetService<MainWindow>()` |
| **计算属性** | 基于其他属性计算的值 | `public bool HasError => !string.IsNullOrEmpty(ErrorMessage);` |
| **partial void** | 属性变化时的钩子方法 | `partial void OnUsernameChanged(string value)` |

### 面试要点 ⭐

1. **解释MVVM在登录中的应用**
   - View: `Login.xaml` 定义UI
   - ViewModel: `LoginViewModel` 处理业务逻辑
   - Model: 用户数据模型（本例较简单，未单独定义）

2. **为什么密码框不能直接绑定？**
   - 安全考虑，`PasswordBox.Password` 不是依赖属性
   - 通过 `PasswordChanged` 事件手动获取

3. **async/await 的优势**
   - 不阻塞UI线程，保持界面响应
   - 代码简洁，避免回调地狱

4. **CommunityToolkit.Mvvm 的作用**
   - 减少样板代码（boilerplate）
   - 源生成器自动生成属性和命令
   - 提高开发效率
