## 📚 功能概述

EquipmentInfo 页面是一个**设备信息展示页面**，功能包括：

1. **显示设备列表**：加载并显示所有设备
2. **订阅数据更新消息**：当其他页面修改设备数据后，自动刷新
3. **导航到预约列表**：点击设备可查看该设备的预约信息

## ViewModel 代码详解

### 完整代码

```csharp
public class EquipmentInfoViewModel : INotifyPropertyChanged
{
    private readonly Json _jsonData = new Json();
    public IRelayCommand OpenReservationListCommand { get; }

    public ObservableCollection<EquipmentInfoModel> EquipmentList { get; } = new();

    public ICommand NavigateCommand { get; }

    public EquipmentInfoViewModel()
    {
        LoadEquipment();

        OpenReservationListCommand = new RelayCommand<object>((param) =>
        {
            WeakReferenceMessenger.Default.Send(new ChangePageMessage
            {
                PageKey = "ReservationList",
                Parameter = param
            });
        });

        // 订阅设备数据更新消息
        WeakReferenceMessenger.Default.Register<EquipmentDataUpdatedMessage>(this, (recipient, message) =>
        {
            // 重新加载设备数据
            LoadEquipment();
        });
    }

    private void LoadEquipment()
    {
        try
        {
            // 使用 JsonDataService 获取最新的设备数据
            var equipmentJson = JsonDataService.Instance.GetEquipmentInfoJson();
            var equipment = JsonConvert.DeserializeObject<List<EquipmentInfoModel>>(equipmentJson);
            EquipmentList.Clear();

            if (equipment != null)
            {
                foreach (var item in equipment)
                {
                    EquipmentList.Add(item);
                }
            }
        }
        catch (Exception ex)
        {
            System.Windows.MessageBox.Show($"加载设备信息失败: {ex.Message}");
        }
    }

    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged(string propName) =>
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propName));
}
```

## 核心功能解析

### 1. 数据加载

```csharp
private void LoadEquipment()
{
    try
    {
        // 步骤 1：获取 JSON 字符串
        var equipmentJson = JsonDataService.Instance.GetEquipmentInfoJson();

        // 步骤 2：反序列化为对象列表
        var equipment = JsonConvert.DeserializeObject<List<EquipmentInfoModel>>(equipmentJson);

        // 步骤 3：清空现有数据
        EquipmentList.Clear();

        // 步骤 4：添加新数据
        if (equipment != null)
        {
            foreach (var item in equipment)
            {
                EquipmentList.Add(item);
            }
        }
    }
    catch (Exception ex)
    {
        System.Windows.MessageBox.Show($"加载设备信息失败: {ex.Message}");
    }
}
```

**数据流程**：

```
Json.cs (_EquipmentInfo)
    ↓ (JSON 字符串)
JsonDataService.Instance.GetEquipmentInfoJson()
    ↓ (返回字符串)
JsonConvert.DeserializeObject<List<EquipmentInfoModel>>()
    ↓ (反序列化为对象)
EquipmentList.Clear()
    ↓ (清空旧数据)
foreach 添加到 EquipmentList
    ↓ (触发 CollectionChanged)
UI 自动更新
```

**为什么要 Clear 再添加？**

```csharp
// 方式 1：Clear 再添加（推荐）
EquipmentList.Clear();
foreach (var item in newData)
{
    EquipmentList.Add(item);
}
// 优点：UI 知道发生了变化
// 触发次数：1 次 Clear + N 次 Add

// 方式 2：重新赋值（错误）
EquipmentList = new ObservableCollection<EquipmentInfoModel>(newData);
// 问题：改变了引用，UI 绑定失效！
// EquipmentList 属性必须是只读（只有 getter）

// 方式 3：使用 LINQ（不推荐，性能差）
EquipmentList.Clear();
newData.ForEach(item => EquipmentList.Add(item));
```

### 2. 消息订阅机制

#### 订阅消息

```csharp
public EquipmentInfoViewModel()
{
    LoadEquipment();  // 初始加载

    // 订阅设备数据更新消息
    WeakReferenceMessenger.Default.Register<EquipmentDataUpdatedMessage>(
        this,                    // 接收者（当前 ViewModel）

            // 收到消息后重新加载数据
            LoadEquipment();
        });
}
```

## 消息传递模式详解

### 观察者模式（Observer Pattern）

**消息传递是观察者模式的一种实现**。

**传统事件 vs 消息传递**：

```csharp
// ===== 传统事件（紧耦合） =====
public class EditViewModel
{
    public event EventHandler? DataUpdated;  // 定义事件

    private void Save()
    {
        // 保存数据...
        DataUpdated?.Invoke(this, EventArgs.Empty);  // 触发事件
    }
}

public class EquipmentInfoViewModel
{
    private EditViewModel _editViewModel;

    public EquipmentInfoViewModel(EditViewModel editViewModel)
    {
        _editViewModel = editViewModel;
        _editViewModel.DataUpdated += OnDataUpdated;  // 订阅事件
        // 问题：必须知道 EditViewModel 的存在，强耦合
    }

    private void OnDataUpdated(object? sender, EventArgs e)
    {
        LoadEquipment();
    }
}

// ===== 消息传递（松耦合） =====
public class EditViewModel
{
    private void Save()
    {
        // 保存数据...
        WeakReferenceMessenger.Default.Send(new EquipmentDataUpdatedMessage());
        // 不需要知道谁在监听
    }
}

public class EquipmentInfoViewModel
{
    public EquipmentInfoViewModel()
    {
        WeakReferenceMessenger.Default.Register<EquipmentDataUpdatedMessage>(this, (r, m) =>
        {
            LoadEquipment();
        });
        // 不需要知道谁在发送
    }
}
```

**优势对比**：

| 特性 | 传统事件 | 消息传递 |
|------|---------|---------|
| 耦合度 | 高（发布者和订阅者相互依赖） | 低（通过消息中介） |
| 内存泄漏 | 容易（需手动取消订阅） | 不易（弱引用） |
| 跨模块通信 | 困难 | 容易 |
| 类型安全 | 强 | 强（泛型） |

### 消息类型设计

```csharp
// 1. 无数据消息（只通知）
public record EquipmentDataUpdatedMessage;

// 2. 携带数据的消息
public record EquipmentSelectedMessage
{

public record DataRequestMessage
{

{

```

## 内存管理和最佳实践

### 1. 取消消息订阅

```csharp
public class EquipmentInfoViewModel : IDisposable
{
    public EquipmentInfoViewModel()
    {
        WeakReferenceMessenger.Default.Register<EquipmentDataUpdatedMessage>(this, OnDataUpdated);
    }

    private void OnDataUpdated(object recipient, EquipmentDataUpdatedMessage message)
    {
        LoadEquipment();
    }

    // 实现 IDisposable
    public void Dispose()
    {
        // 取消所有消息订阅
        WeakReferenceMessenger.Default.UnregisterAll(this);
    }
}
```

**何时需要手动取消订阅？**

```csharp
// ✅ 使用 WeakReferenceMessenger：通常不需要
// 弱引用会自动处理，ViewModel 被 GC 回收时自动取消订阅

// ⚠️ 特殊情况需要手动取消：
// 1. ViewModel 是 Singleton
// 2. 需要临时停止接收消息
// 3. 在 ViewModel 生命周期内多次订阅/取消订阅
```

### 2. 避免内存泄漏

```csharp
// ❌ 错误：在 Lambda 中引用大对象
public EquipmentInfoViewModel()
{
    var largeObject = LoadLargeData();  // 大对象

    WeakReferenceMessenger.Default.Register<SomeMessage>(this, (r, m) =>
    {
        // Lambda 捕获 largeObject，导致内存泄漏
        Process(largeObject);
    });
}

// ✅ 正确：不捕获大对象
public EquipmentInfoViewModel()
{
    WeakReferenceMessenger.Default.Register<SomeMessage>(this, (r, m) =>
    {
        var largeObject = LoadLargeData();  // 每次加载
        Process(largeObject);
    });
}
```

### 3. 消息通道（Channel）

```csharp
// 使用不同通道隔离消息
WeakReferenceMessenger.Default.Register<DataUpdatedMessage, string>(
    this,
    "Channel1",  // 通道名称
    (r, m) =>
    {
        // 只接收 Channel1 的消息
    });

// 发送到特定通道
WeakReferenceMessenger.Default.Send(new DataUpdatedMessage(), "Channel1");
```

### 面试要点

**Q1：如何实现页面间的数据同步？**

A：使用消息传递机制（WeakReferenceMessenger）。当一个页面修改数据后，发送消息通知其他页面。其他页面订阅该消息，收到通知后重新加载数据，实现自动同步。

**Q2：为什么要使用 ObservableCollection 而不是 List？**

A：ObservableCollection 实现了 INotifyCollectionChanged 接口，当集合发生变化（添加、删除、清空）时会自动通知 UI 更新。List 修改后 UI 不会自动刷新。

**Q3：消息传递和事件有什么区别？**

A：消息传递是松耦合的，发送者和接收者互不依赖，通过消息中介通信。传统事件是紧耦合的，订阅者需要持有发布者的引用。消息传递更适合跨模块通信，且使用弱引用避免内存泄漏。

**Q4：如何避免消息订阅导致的内存泄漏？**

A：使用 WeakReferenceMessenger 的弱引用机制，当 ViewModel 被 GC 回收时会自动取消订阅。如果 ViewModel 是 Singleton，需要手动调用 UnregisterAll 取消订阅。
